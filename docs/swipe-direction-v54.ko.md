# 재발한 iPhone 드래그 방향 오류 보완

사용자는 이전 수정 이후 새 TestFlight 빌드를 설치했다고 답했다. 설치 버전 번호는 아직 받지 못했다. 로컬 iOS 프로젝트는 1.11 (12), 동기화된 웹 리소스는 2026-11-10T00:05:10.305Z이며 v53 입력 코드가 포함돼 있음을 확인했다. 이번 변경은 소스와 임시 웹 번들에만 반영했으며 네이티브 동기화나 앱 빌드는 하지 않았다.

## 추가 재현

v53은 축을 늦게 고정해도, 고정한 뒤에는 교정할 수 없었다. 40번 타일을 처음 아래로 16px 움직인 다음 왼쪽 36px / 아래 16px 위치까지 드래그하면 아래 49번으로 교환했다. v53 Board와 drag-preview를 모두 고정한 브라우저 비교에서 재현했고, 새 코드에서는 왼쪽 39번으로 교환했다. 따라서 첫 수정의 작은 손떨림 검사만으로 전체 경로를 확인하기에는 부족했다.

다른 경로는 마지막 move 이벤트에서 왼쪽 타일을 미리보기로 보여준 뒤, up 이벤트의 좌표만 반대로 전달되는 경우다. v53은 이를 반대쪽 교환으로 처리했다. 해당 좌표 불일치가 사용자 iPhone에서 실제 발생했는지는 아직 확인하지 못했다.

## 동작 변경

- 이미 선택된 축이 있어도 다른 축 이동이 한 칸의 28% 이상이면서 기존 축 이동의 1.5배를 넘으면 그 축으로 교정한다. 일반적인 대각선 흔들림에서는 축을 유지한다.
- 마지막 유효한 미리보기와 up 이벤트의 교환 목적지가 충돌하면 취소한다. up 좌표만으로 다른 이웃을 교환하지 않는다. move 이벤트에서 확인된 의도적인 반전과, move 이벤트 없이 끝나는 빠른 스와이프는 유지한다.
- 제스처 시작 시 캔버스 좌표계와 스케일을 저장하고 client 좌표의 차이를 계산한다. 누른 도중 캔버스 위치나 크기가 1 CSS px 넘게 바뀌면 취소한다.
- 기본 포인터만 받는다. 누른 상태에서 다른 포인터가 들어오면 현재 제스처를 취소해 두 손가락 입력이 섞이지 않게 한다.

## 진단

`input-diagnostics.ts`는 최근 24시간의 제스처 최대 24개, 제스처당 표본 최대 12개를 기기에 저장한다. 처음 움직임과 최근 표본, release 좌표, 판정 사유, 실제 제출 Action을 구분한다. 전체 보드, 계정 식별자, 이메일, 인증 토큰은 포함하지 않는다. 저장소 접근 차단이나 용량 오류가 게임 입력에 영향을 주지 않게 처리했다.

고객센터 → 새 문의 → 버그 제보에서 **입력 기록 추가**를 누르면 앱 버전·빌드 번호와 최근 기록이 문의 초안에 추가된다. 작성한 본문은 보존하고 전체 6,000자 제한을 지킨다. 사용자가 초안을 확인한 뒤 직접 접수하며 자동 업로드는 없다. 기존 고객센터 API를 사용하므로 서버 변경은 없다.

## 검증과 한계

- 타입 검사, 관련 9개 파일 62개 테스트 통과. 프로덕션 웹 번들은 `/private/tmp/puzzle-swipe-v54-build`에 생성했다. 기존 대형 chunk 경고는 남아 있다.
- 실제 Board/CascadeBoard 격리 브라우저: 특수 아이템 6종 × 곡선 드래그 네 방향 24건, 일반 포인터 드래그 네 방향 4건, 로켓+폭탄 조합 네 방향 4건.
- 반대 release, 직교 release, 화면 위치 변경, 두 번째 포인터, 원점 복귀 5건 모두 다른 교환 없이 취소. move에서 확인된 반전, 빠른 스와이프, 아이템 탭 정상 처리.
- 4개 매치로 로켓이 생성된 뒤 즉시 해당 로켓을 39 → 38로 드래그해 turn 2 및 정상 잠금 해제 확인.
- 폭 320 / 430에서 모션 축소로 네 방향 8건, 즉시 연속 입력은 한 교환만 처리. 오류 로그 0건 확인.
- 고객센터에서 기존 본문을 보존한 채 3,124자 진단 초안이 추가되고 중복 버튼이 사라지는 것을 확인했다. 문의를 전송하지 않았으며 fixture는 API 변경 요청을 차단한다.

이는 합성 touch PointerEvent와 브라우저 포인터 검증이다. iPhone 실기기에서 신고된 사례의 원인을 모두 확정하거나, 재발이 완전히 없어졌음을 검증한 결과는 아니다. 새 앱 빌드에서 재발한다면 입력 기록을 첨부한 제보로 미리보기·release·실제 Action이 어디서 달라지는지 구분할 수 있다.

증거는 `output/verification/swipe-direction-v54/`에 보관한다. 운영 배포, 네이티브 동기화, 앱 빌드, Git 커밋·푸시는 수행하지 않았다.
