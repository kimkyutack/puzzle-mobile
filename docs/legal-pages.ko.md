# 공개 정책 페이지

2026-11-11 작성. 공개 사업자 정보는 사용자가 제공한 사업자등록증명에서 확인했다. 증명서 원본, 주민등록번호, 발급·접수번호 및 세무서 담당 연락처는 저장소나 공개 페이지에 포함하지 않는다. 개인정보 담당자와 계정 삭제 이메일은 사용자 답변에 따라 대표 김규택 / hiddenstagedev@gmail.com을 사용한다.

## 연결

- `/official/privacy`: 개인정보처리방침
- `/official/terms`: 이용약관
- `/official/account-deletion`: 앱 외부 계정 및 개인정보 삭제 요청
- 기존 `/privacy`, `/terms`, `/account-deletion` 주소도 유지한다. 영어·일본어 주소와 홈페이지 구성은 [공식 홈페이지 문서](official-site.ko.md)를 참고한다.

운영 배포 후 현재 도메인 `https://puzzle-mobile.ddr1323.workers.dev` 뒤에 위 경로를 붙여 사용한다. `/api`와 `/admin` 밖의 공개 GET/HEAD이며 로그인, DB 조회, 쿠키 설정을 하지 않는다. POST/DELETE는 405로 거절한다. 설정의 ‘약관 및 개인정보’에서 동일한 운영 주소를 웹/네이티브 브라우저로 연다. 인앱과 운영 콘솔의 계정 삭제는 동일한 서버 정리 경로를 사용한다.

외부 계정 삭제는 이메일 접수 방식이다. 메일 버튼은 초안만 열며, 직접 전송해야 접수된다. 일반 이메일 프로그램이 없는 환경에서도 주소를 복사해 전송할 수 있도록 주소·제목·필요 정보를 문서에 제공한다. 사이트 자체에서 익명 삭제 요청을 신뢰하거나 타인 계정을 바로 삭제하지 않는다. 운영자는 이메일 수신, 본인/법정대리인 확인, 처리, 결과 회신을 담당해야 한다.

## 배포·스토어 제출 전 실제 운영과 맞출 사항

아래 항목은 현재 코드와 출시 전 확인 사항을 정리한다.

1. 앱은 계정 생성·게임 시작 전에 생년월일로 연령을 확인하고 생년월일 원문을 보관하지 않는다. 만 14세 미만의 동의 요청을 접수하면 서버가 입력한 보호자 이메일로 안내를 발송한다. 안내 메일 발신 주소는 `consent@hiddenstage.app`이고 회신은 공식 운영 메일함 `hiddenstagedev@gmail.com`으로 받는다. `/admin/guardian-consents`에서 발송 상태를 보고, 회신 보낸 주소, 요청 번호, 법정대리인 여부와 명시적 의사를 확인한 뒤 승인 또는 거절한다. 회신이 모호하거나 주소가 다르면 승인하지 않는다. 철회 요청은 기존 회신과 요청 번호를 확인한 뒤 같은 화면에서 처리한다. 운영 메일함의 동의 증빙은 접근 권한을 제한하고 이용·철회·탈퇴와 법령상 보관 조건에 따라 정리한다.
   - 아동 계정에는 광고·스토어 결제·외부 로그인·소셜 기능을 제공하지 않는다. 미확인 및 청소년 계정도 보상형 광고 SDK를 호출하지 않는다. 국내 기준으로 만 19세 이상 확인 계정만 보상형 광고를 이용할 수 있다. 생년월일을 저장하지 않으므로 연령 구간의 자동 갱신은 제공하지 않는다.
   - 운영의 D1에 `0013_age_access.sql`을 먼저 적용한다. 스토어·테스트 트랙에서 연령 확인 화면이 포함된 앱을 배포할 수 있게 준비한 다음 서버 연령 확인을 시행한다. 기존 앱에는 새 절차 화면이 없어 시행 즉시 새 앱이 필요하다. App Store와 Play Console의 대상 연령·광고·데이터 공개는 실제 빌드 기준으로 갱신한다.
   - 운영 계정의 Cloudflare Email Sending에서 `hiddenstage.app`을 등록하고 발신 도메인 인증을 확인한다. D1에 `0015_guardian_email.sql`을 적용한 다음 Worker를 배포한다. 배포 후 새로 접수된 건부터 자동 발송된다. 자동 발송이 실패한 건은 운영 콘솔에서 수동 발송할 수 있다. 발송 여부 확인이 필요한 건은 Cloudflare 발송 기록부터 확인한다. 공개 전에 수신 → 회신 → 승인 → 아동 기기 시작, 그리고 거절·철회를 각각 확인한다.
2. 계정 삭제 API는 플레이어 행과 관련 세션·정원·진행·광고·소셜·동의·일반 문의 기록을 하나의 D1 배치에서 삭제한다. 운영 콘솔 소유자는 외부 요청자의 본인 또는 법정대리인 여부를 확인한 뒤 사용자 상세에서 동일한 삭제를 실행한다. 이전 방식으로 비활성 처리한 계정은 예약 작업이 배치로 정리한다. 유료 거래와 실제 소비자 불만·분쟁만 아래 기간에 따라 별도 보관하고, 운영 콘솔의 법정 보관 기록 메뉴는 소유자만 정확한 거래·문의 번호로 조회할 수 있다.
   - 실결제는 결제·공급·환불 중 가장 늦은 시각으로부터 5년 보관한다. 거래 식별값, 상품과 시각 등 필요한 필드만 남긴다. 테스트 결제와 미결제 구매 준비는 보관 대상이 아니다. 회계·세무용 정산 자료는 과세기간 및 거래 유형에 따른 기준으로 스토어 정산 증빙에서 별도 관리한다.
   - 고객센터의 일반 문의·버그 제보는 삭제한다. 실제 소비자 불만·분쟁으로 확인된 건은 탈퇴 전에 운영 콘솔의 문의 상세에서 보관 대상으로 지정하고 필요한 사실·처리 결과만 요약한다. 보관 기한은 접수·처리 기록을 기준으로 3년이다. 일반 문의 유형이나 결제 문의 분류만으로 보관 대상이 되지 않는다.
   - 스토어와 Apple 연결 해제를 처리하는 데 필요한 기존 전송 대기 정보는 계정 식별 정보를 제거한 뒤 성공 즉시 지우고, 삭제 후 남은 실패 대기는 최대 7일 동안 정리한다. 운영 메일함에 별도로 저장된 문의·동의 회신과 내보낸 파일은 DB 삭제 범위 밖이므로 운영자가 같은 기준으로 파기한다.
   - 개인정보 처리 업무의 관리자 접속기록은 본문·이전/이후 값과 분리하고, 담당자·접속지·업무·대상 참조·일시만 기본 1년 보관한다. 5만 명 이상 등 고시상 2년 조건에 해당하면 `PRIVACY_ACCESS_RETENTION_YEARS=2`로 전환하고 기존 접속기록의 기한도 조정한다.
   - D1 복원은 트래픽을 차단한 상태로 진행한다. 복원 전 소유자 세션으로 `GET /api/admin/privacy/erasure-receipts`의 `next`를 `after`로 전달해 모든 30일 삭제 해시 목록을 별도의 제한된 위치에 받는다. 복원 후 마이그레이션을 적용하고 점검을 켠 뒤, 같은 경로에 `POST {items}`로 100개씩 복원한다. `POST /api/admin/privacy/replay-erasures`에 빈 객체를 보내 시작하고, 응답의 `next`를 `after`로 넘겨 마지막까지 삭제를 재적용한다. 복원 전에 보관 중인 거래·분쟁 기록도 보존해 복원 시 누락되거나 기한이 지난 기록이 재공개되지 않도록 대조한다. 검증 후 내보낸 삭제 목록을 폐기한다.

3. Cloudflare·Google·Apple의 국외 처리와 제공자 정책을 안내했다. 실제 DB·로그·백업 위치, 이전 국가·수탁자 연락처·항목·시점·기간 및 적용되는 국외 이전 근거를 운영 계약·서비스 설정 기준으로 확정해야 한다. 글로벌 인프라 설명이나 제공자 링크만으로 별도 동의/고지 요건이 충족되는 것은 아니다.
4. 법정 보관 기간(거래 5년, 불만·분쟁 3년, 표시·광고 6개월)은 해당 기록이 실제 발생하고 법령상 의무가 적용되는 경우에 한한다. 일반 문의나 모든 광고 시청 기록에 일률적으로 적용하지 않는다. 미성년자 결제·환불 처리는 실제 스토어 상품·정책과 맞춰야 한다.
5. `config/legal.json`에 공개 사업자·연락처·시행일·버전을 모았다. 시행일은 첫 공개 전에 최종 적용일과 맞추고, 변경 사항은 앱 공지 등 실제 운영 경로로 안내한다. 이번 작업은 운영 배포나 네이티브 동기화를 포함하지 않는다.
