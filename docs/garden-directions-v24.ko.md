# 꾸미기 장식 네 방향 · v24

2026-11-04. 모든 배치 아이템이 `0 → 90 → 180 → 270 → 0` 순서로 전환된다. 방향 버튼에는 현재 각도가 표시된다. 단일 배치와 이동뿐 아니라 여러 개 연속 배치에서도 방향을 선택한다.

## 원화와 렌더링

기존 앞면 PNG는 그대로 보존한다. 기본 장식·건물·동물 17종과 축제 스타일 3종에 별도 뒷면 원화 20장을 built-in `image_gen`으로 제작했다. 0/90은 기존 앞면과 그 좌우 방향, 180/270은 새 뒷면과 그 좌우 방향을 사용한다. 벤치의 뒷등받이, 온실의 뒷벽, 버섯 조명의 창문 없는 면, 동물의 등과 꼬리처럼 반대편 모습이 보인다. 원화 전체를 평면 회전해 거꾸로 세우지 않는다. 산책로 바닥은 등각 평면에서 회전한다.

- 원본: `packages/garden-world/art/source/directions-v24/`
- 런타임: `packages/garden-world/art/runtime/directions-v24/`
- 정확한 프롬프트·참조·생성 경로: `packages/garden-world/art/directions-v24-prompts.json`
- 재현: `node --import tsx tools/garden-world/build-directions.ts`

파생 이미지는 기존 앞면의 캔버스 크기에 맞춰 비율을 보존하고 발/바닥 기준선에 정렬한다. `gardenDirectionArt`가 디자인과 방향에 맞는 그림을 고르고, `gardenObjectBounds`를 실제 렌더·배치 미리보기·알파 클릭/드래그에서 같이 사용한다. 회전 후에도 클릭 영역이 앞면 그림에 남지 않는다. 동물은 설정한 방향으로 시작하고 산책을 시작하면 진행 방향에 맞춰 몸을 돌린다. 기존 하품·수면 모션은 유지한다.

## 배치와 저장

모든 장식 카탈로그가 네 각도를 허용한다. 0/180은 원래 가로·세로 칸을, 90/270은 바꾼 칸을 차지한다. 전체 칸의 점유·잠긴 구역·지도 경계를 검사한다. 실제 UI에서도 세로로 놓은 벤치를 가로로 돌릴 때 가로등과 겹치면 설치를 차단하는 것을 확인했다.

서버의 일반 배치·이동과 일괄 배치 검증도 네 각도를 받는다. 45도 등 다른 값은 거절한다. 기존 저장 JSON의 `rotation` 필드와 0/90 배치는 호환하며 새 DB 스키마는 필요 없다. 방향을 바꾸거나 이동해도 다시 구매하지 않는다.

## 검증

- 타입 검사와 정원 관련 6파일·48검사 통과. 네 각도 순환, 앞/뒤·축제 원화 선택, 점유 칸, 경계, 연속 배치 방향, 동물 초기 방향 포함.
- 실제 Worker + 임시 D1 HTTP 검증: 일반 배치의 네 방향 저장·재조회, 잘못된 각도 거부, 일괄 배치의 180/270도, 구매·중복키·원자성·재화 보존. 운영 DB나 실제 사용자 계정으로 테스트하지 않았다.
- CUA 실제 홈: 벤치 구매 → 0/90/180/270 전환 → 270도 뒷면을 직접 드래그 → 저장 → 새로고침 후 270도/좌표/원화 복원 → 뒷면 클릭 → 270에서 0으로 순환과 충돌 차단. 390×844와 320×740에서 확인했으며 320px 버튼/문서 수평 넘침은 없었다.
- 원본 앞/뒤 그림이 같은 것을 반복하지 않는지 뒷면 20종을 시각 확인했다. 비교용 `tools/garden-world/directions-v24.html`은 실제 WorldMap을 사용하고 API/계정에 연결하지 않는다.
- `npm run native:release` 통과. JS/CSS와 새 PNG 20장이 웹/iOS/Android에서 SHA-256으로 일치한다. 실제 APK/IPA 설치는 하지 않았다.
- 증거: `output/verification/garden-directions-v24/`.
