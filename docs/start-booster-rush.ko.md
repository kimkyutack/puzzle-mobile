# 시작 아이템 무제한 시간 이벤트

기본 일정은 매일 한국 시간 12:00, 18:00, 21:00부터 각각 10분입니다. 모든 사용자가 같은 시간에 이용합니다. 운영 콘솔 → 이벤트 → **시작 아이템 무제한**에서 활성화 여부와 시작 시간을 변경할 수 있으며, **매 3시간**으로 한 번에 설정할 수도 있습니다.

- 대상: 시작 화면의 로켓·꽃폭탄·무지개등. 종류마다 하나씩, 세 종류 모두 선택할 수 있습니다.
- 이벤트 중에는 보유 수량이 0이어도 선택 가능하며 일반 수량과 지급 수량 모두 차감하지 않습니다.
- 판 안에서 사용하는 망치·쓸기 등의 도구, 하트와 다른 구매는 기존 규칙을 유지합니다.
- 홈에 진행 중인 이벤트와 남은 시간이 표시됩니다. 시작 화면·이벤트 페이지에는 일정과 10분 이용 규칙도 안내합니다.
- 이미 시작한 판은 이벤트가 열려도 아이템을 추가하거나 배치를 바꾸지 않습니다. 이벤트 중 배치한 아이템은 종료 뒤에도 해당 판에 남습니다.
- 서버가 새 판을 만드는 시각으로 자격을 판단합니다. 이벤트 중 무료 선택으로 보낸 요청이 종료 후 도착하면 수량을 차감하지 않고 재선택 안내를 반환합니다.
- 종료되거나 운영자가 중지하면 시작 화면에서 선택을 초기화하여 보유 아이템을 뜻밖에 사용하지 않도록 합니다.
- 23:55처럼 자정을 넘는 10분 구간도 처리합니다. 일정은 중복·겹침을 막기 위해 서로 10분 이상 간격을 둡니다.

인증에서 이미 읽은 운영 설정을 재사용하므로 판 시작을 위한 추가 DB 조회나 예약 Cron이 필요하지 않습니다. 타이머는 기존 게임의 1초 화면 갱신을 사용합니다. 퍼즐 엔진과 네트워크 행동 저장 방식은 변경하지 않습니다.

기존 설정 JSON에 필드가 없으면 기본 일정을 적용하므로 DB 마이그레이션은 필요하지 않습니다. 설정 변경은 기존 운영 기록·사유·권한·revision 충돌 검사를 그대로 사용합니다. 이 기능 이전의 Worker로 되돌릴 때는 이전 설정 검증기가 새 필드를 인식하지 못하므로, 운영 runtime JSON의 `startBoosterRush` 필드도 함께 이전 형식으로 복원해야 합니다.

## 검증

- 시작/종료 밀리초 경계, 한국 시간 자정, 다음 날 일정, 매 3시간, 중지, 중복/겹침/잘못된 시간 검증.
- 실제 SQLite API: 보유 0개 선택, 일반·지급 수량 보존, 인게임 도구의 기존 차감, 종료 직후 무료 요청 거절, 진행 중 판 유지, 요청 재전송 중복 방지.
- 실제 앱 390×844: 홈 카운트다운, 세 종류 ∞/선택 표시, 0개 상태로 레벨 31 시작. 실제 로컬 Worker 저장 결과에서도 세 종류 수량이 모두 0인 채로 유지됨을 확인.
- 전체 73개 파일 / 516개 테스트, TypeScript, 관리자 빌드, 네이티브 Release 웹 리소스 동기화 통과.
- 근거: `output/admin-console/tests-start-rush-all.log`, `tests-start-rush.log`, `rush-browser-proof.json`, `screenshots/rush-home.png`, `rush-start-selected.png`, `rush-playing.png`.

운영 서버 배포: `65f90fac-7aea-4ea4-86d5-b7b7e383d610`. 배포 후 운영 API의 활성 기본 일정, 점검 꺼짐, 게임 health, 관리자 새 JS와 익명 접근 차단을 읽기 전용으로 확인했습니다. 운영 계정의 재화·게임 판을 검증용으로 변경하지 않았습니다. 네이티브 웹 리소스 536개가 iOS/Android와 각각 해시 일치합니다. 앱 아카이브와 스토어 업로드는 수행하지 않았습니다.
