# 친구

하단 메뉴는 상점 → 친구 → 홈 → 길드 → 이벤트 순서입니다. 친구는 모달이 아닌 `#/friends` 페이지이며 목록, 추천, 하트, 랭킹 탭이 있습니다. 이전 진행 판이나 재화 기록을 초기화하지 않습니다. 기존 Lumi 그림과 PNG UI 소재를 재사용합니다.

- 친구 추가는 요청 → 상대 수락으로 양쪽 목록에 저장됩니다. 받은 요청의 거절도 지원합니다. 기존 친구는 '이미 친구예요', 보낸 요청은 '친구 요청 중' 비활성 버튼으로 표시합니다.
- 추천은 같은 길드, 비슷한 레벨 순서의 실제 계정 최대12명입니다. 자신·기존 친구·대기 요청·양방향 차단·삭제된 계정을 제외합니다. 친구와 대기 요청 합계는200명, 하루 새 요청은20회입니다.
- 친구 하트 요청은4시간마다, 요청당5개입니다. 요청에 한 번씩 도울 수 있으며 보내는 사람의 플레이 하트를 소모하지 않습니다. 친구 사이의 일일 보내기/받기는 각각10개이고 UTC 자정에 초기화됩니다. 기존 길드 지원의 일일 한도와는 별도입니다.
- 선물은 기존 하트 보관함 계약을 사용합니다. 친구/길드 합산 보관한도20개이며, 하트가 가득 차면 선물을 보관하고 나중에 수령합니다. 친구 페이지와 기존 선물함 어디서든 같은 선물로 한 번만 수령됩니다.
- 친구 랭킹은 나와 수락한 친구만 포함합니다. 승인된 최고 클리어 기록 `ranking_scores`를 사용하고, 같은 기록은 공동 순위입니다. 화면에서15초 간격과 재진입/포커스 복귀 때 갱신합니다.
- 길드 채팅 이름·멤버의 이름과 아바타, 개인/친구 순위표의 이름과 아바타가 공통 프로필 창을 엽니다. 공개 프로필은 닉네임·레벨·최고 클리어·길드 이름·친구 관계만 반환합니다. 코인/인벤토리/세션 등은 노출하지 않습니다.

## API 및 저장

`0009_friends.sql`은 기존 데이터를 다시 쓰지 않고 friendships, friend_heart_requests, friend_heart_help 테이블과 인덱스를 추가합니다. 모든 변경은 인증, idempotency key, Player 버전 검사, D1 atomic batch를 사용합니다. 친구 관계 변경과 도움은 양쪽 버전을 확인하며, 중복 선물과 동시 한도 초과를 막습니다. 차단/삭제/만료/비친구의 도움은 서버에서 거부합니다.

| 요청 | 용도 |
| --- | --- |
| GET /friends | 목록·추천·받은/보낸 요청·하트 요청·보관 선물 |
| POST /friends/requests | userId로 친구 요청 |
| POST /friends/respond | userId, accept로 수락/거절 |
| POST /friends/hearts/request | 친구에게 하트 요청 |
| POST /friends/hearts/:id/help | 요청에 하트 도움 |
| GET /players/:id/profile | 공개 프로필·친구 상태 |
| GET /rankings?scope=friends | 친구 랭킹 |
| POST /gifts/:id/claim | 기존 선물 수령 |

## 검증

`node --import tsx tools/api-friends-http.ts`는 실제 Worker HTTP와 별도 임시 D1으로 인증·관계 동의·중복/동시성·공개정보 경계·친구 랭킹·하트 수령·한도·차단·만료·실패 시 전체 롤백을 검증합니다. `output/verification/friends-http.json`에 결과를 남깁니다. `--ui`는 이 임시 API와5188 전용 Vite를 띄우고 격리된 UI 테스트 계정을 만듭니다. 실제 플레이어 DB나 기존5173 검수 탭의 저장소를 사용하지 않습니다. 테스트 HTML과 임시 세션은 `.wrangler` 아래에만 생성하며 클라이언트 배포 입력에 포함하지 않습니다.

로컬 개발 DB에0009만 적용했습니다. 운영 DB 마이그레이션/배포와 네이티브 재빌드/설치는 이 작업에 포함하지 않았습니다.
