# 칸별 상자와 자석 레일 검수

- v37의 큰 차양·2×2 그림을 새 구역 맵에서 제거했다. 칸별 상자는 각각 기존 PNG를 사용하고 한 칸씩 독립적으로 손상된다.
- 104레벨의 첫 이동은 상자 12개 중 3개만 제거하고 나머지 9개를 남겼다. 이전 큰 영역을 공유 내구도로 한꺼번에 제거하는 방식과 구분된다.
- 끝·직선·모서리 PNG는 별도로 생성한 실제 래스터 이미지다. 직선과 굽은 레일 모두 칸마다 조합하며 큰 가로세로 이미지로 늘리지 않는다.
- 실제 Board/CascadeBoard/PlayHud를 사용하는 계정·API 없는 Chrome 검사 화면에서 214레벨을 확인했다. 몸통 망치 입력 전후 상태 해시는 `b3172c47`로 같았고 길이도 5를 유지했다. 앞 끝 타격 후 길이 4, 뒤 끝 타격 후 길이 3이 되었으며 각각 입력이 `idle`로 돌아왔다.
- 718레벨의 긴 굽은 레일과 개별 상자·서리·덩굴 조합을 확인했다. 레일 위에 큰 공유 내구도 숫자는 표시하지 않는다. 4개 목표가 헤더 2행 안에 들어간다.
- 실제 114레벨을 검증된 자연 교환 5회로 클리어했다. 최종 상태는 `won`, 입력 `idle`, 활성 이펙트 0이며 검사 탭의 콘솔 오류는 없었다.
- 캡처는 폭 390 CSS px의 격리 검사 화면이다. Chrome의 잘못된 clip 결과를 피하기 위해 전체 뷰포트를 저장한 뒤 게임 부분을 추출했다. 이는 실물 iPhone·Android 프레임 측정이나 사람의 체감 난이도 검증은 아니다.
- `output/verification/progression-v39/214-before.png`, `718-before.png`, `214-ui.json`, `114-win-ui.json`에 화면과 상태 증거를 보관한다. 단계별 전후 캡처는 브라우저 캡처 좌표에 차이가 있어 위치·크기 비교의 근거로 삼지 않는다. 축소 판정은 이벤트 footprint와 상태 해시·길이로 검증했다.
- 전체 71개 파일 / 492개 테스트와 TypeScript·Worker 패키징 검사를 통과했다. iOS·Android 앱 리소스 536개가 최종 웹 빌드와 해시 일치하며 Release API 검사도 통과했다.

프롬프트와 생성 방식은 `packages/assets/magnet-rail-v39-prompts.json`에 기록했다. 검수용 버튼·테스트 계정은 제품 화면에 추가하지 않았다.
