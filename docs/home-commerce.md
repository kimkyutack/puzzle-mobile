# 정돈된 홈과 공략 패키지

2026-11-02 사이드 채팅 요청 구현. 첨부 Royal Match 이미지는 정보 배치 참고이며 원본 캐릭터·아이콘을 추출하지 않았다. 기존 구름정원의 실제 PNG를 재사용했다.

## 홈

- 프로필·같은 재화창 세 개·설정을 한 줄로 정렬. 재화 수량이 커지면 헤더에서만 한국어 단위로 줄여 표시하고 상점에는 정확한 수량을 표시한다.
- 정원 활동 진행은 한 줄의 보상 바에 모은다. 무료 선물/하트/특별 패키지/선물함 네 진입점만 양쪽에 배치한다.
- 일반 홈은 완성된 정원 소품만 보여 준다. 복원 편집에서는 모든 Before/After와 기존 작업 흐름을 유지한다.
- 플레이/정원 꾸미기를 큰 두 버튼으로 유지하고 복원 진행은 정원 버튼 안으로 이동한다.
- 하단은 상점/순위/홈/길드/패스 다섯 개. 아이콘을 약53px로 키우고 가운데 홈은81px로 강조한다.
- ArtSurface가 자신의 루트 크기 변경에도 렌더러를 resize하도록 수정해 안전 영역 변경 뒤 하단34px가 잘리던 미리보기 문제를 해결한다.

가격은 기획 기준값이다. 실제 결제 버튼은 스토어 SDK가 반환한 현지화 가격만 사용한다. 스토어 미연결 상태는 기준 가격으로 명시하며 구매를 실행하지 않는다. 별도 실패/승리 보장이나 순위 점수는 지급하지 않고, 순위에는 실제 클리어 기록이 반영된다.

달력은 서버 UTC 기준이며 타이머는 페이지 재진입으로 초기화하지 않는다. 월간 연쇄는 월말 종료 후 새달에 다시1단계부터 열린다. 구매가 확인된 단계만 다음 단계를 연다. 환불한 단계는 환불 완료로 표시하고 같은 기간 재구매나 다음 단계 해금에 사용하지 않는다. 이미 준비한 정상 스토어 승인 대기는 원래 예약한 판매 기간에 귀속한다.

## 서버·결제 연결

GET /api/offers는 현재 계정의 상품/판매 기간/구매·잠금·환불 상태를 반환한다. 기존 /purchases/prepare와 /purchases/verify를 사용하며, 권위적인 상품 구성은 서버 PRODUCTS에서 결정한다. 예약은 재화를 지급하지 않는다. 기존 영수증 검증·거래 중복 방지·원자적 재화 지급·환불·구매 복구 흐름을 재사용한다.

새 테이블 없이 기존 purchase_intents.season_id에 패스의 시즌 또는 패키지의 판매 기간 식별자를 저장한다. 패스의 season_owners 처리는 product.kind==='pass'에만 적용한다. 일반 /catalog는 기존 상품을 유지하고 새 패키지는 /offers에서만 표시한다.

실제 판매 전에는 위6개 SKU를 양쪽 스토어에 소모품으로 등록하고 실제 가격·상품 상태를 설정해야 한다. 기존 네이티브 결제와 서버 공급자 설정도 필요하다. 보상 구성을 바꿀 때는 기존 결제 SKU를 덮어쓰지 말고 새 버전 SKU를 사용한다.

## 검증과 범위

- TypeScript, 전체 Vitest18파일129개 통과.
- tools/check-commerce-offers.ts: 영속 상태와 분리한 실제 workerd/D1에서 정상 초기 계정과 실제1~4레벨 클리어를 사용. 단계 순서/기간/예약 무지급/중복/환불/월 전환/늦은 승인/랭킹 기록 보존9개 검사 통과.
- 구매 확인 이력은 해당 격리 DB에만 넣은 private fixture이며 실제 스토어 결제 검증을 의미하지 않는다. 공개 테스트 지급 API를 추가하지 않았다.
- tools/preview-home-commerce.ts: 별도 Vite 서버와 임시 Chrome에서360/390/430px 및59/34px 안전 영역으로 홈과3종 패키지·목록 끝 및 큰 재화/전체 복원 상태16화면 캡처. 대표 API 응답을 가로채 렌더링을 검수했으며 실제 사용자 계정·구매는 호출하지 않았다.
- 미리보기: output/verification/home-commerce/home-390.png 및 chain-390.png. API/화면 보고서는 같은 폴더의 api.json, visual.json에 있다.
- 최초 구현의 빌드 검사는 /private/tmp/puzzle-home-commerce-build에 격리했다.
