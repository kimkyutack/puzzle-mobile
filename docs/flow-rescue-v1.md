# 구름길 구조대 첫 에피소드와 퍼즐 흐름 개선

> 2026-11-05 변경: 현재 구조대는 하루 한 번 아이템을 받는 미니게임입니다. 아래 내용은 최초 구현 기록이며, 보상·재도전·진행 저장의 현재 규칙은 [일일 구조대 문서](./daily-rescue.ko.md)를 따릅니다.

2026-11-03 구현. 기존 정원 복원 대화19편을 유지하며 첫 직접 플레이 에피소드를 추가했습니다. 이후 물에 잠긴 작업실/폭풍 온실/우편 비행선은 후속 기획이며 이번 구현에 포함하지 않습니다.

## 사용 경로와 이야기

7판을 완료한 계정(현재 레벨8 이상)은 홈의 **루미의 기록 → 구름길 구조대 → 토리 도와주기**에서 시작합니다. 이미 그 이후로 진행한 계정도 같은 곳에서 열 수 있습니다. 매 판 강제 모달을 추가하지 않습니다.

토리가 꽃빛축제 초대장을 배달하다 끊어진 구름다리 앞에 멈췄습니다. 세 상자를 열 때마다 실제 나무 다리 PNG가 연결되고, 세 번째 조각이 이어지면 토리가 반대편 정원으로 이동합니다. 상자들은1/2/3겹으로 순차적인 복원 반응을 보여줍니다. 기존 엔진의 교환·특수 타일을 그대로 사용합니다. 제한시간을 강요하지 않는18이동 이야기 퍼즐입니다.

이 도전은 일반 판을 교체하거나 중단하지 않습니다. 하트/보유 도구를 사용하지 않으며 일반 레벨·별·코인·랭킹 보상을 변경하지 않습니다. 진행은 계정별 `garden-rescue-bridge-v1-<id>` 행동 로그로 이 기기에 보관하고, 다시 열 때 엔진 재생으로 복구합니다. 패배 시 재도전, 완료 후 다시 플레이를 지원합니다. 나가기는 기록장, 완료 뒤 정원으로는 실제 홈으로 돌아갑니다.

## 완료 저장

`POST /api/story/episodes/bridge-v1/complete`는 로그인,7회 클리어 해금, 일반 swap/tap 행동만의 엄격한 입력과 서버 엔진 재생 승리를 확인합니다. 보상이나 정상 Run을 건드리지 않고 기존 `story_seen` 테이블에 `rescue:bridge-v1` 한 행을 저장합니다. 일반 감상 API로 완료를 위조할 수 없습니다. 중복/동시 완료는 `ON CONFLICT DO NOTHING`으로 한 번만 기록됩니다. 별도 스키마 마이그레이션은 필요하지 않습니다.

`GET /story`는 완료한 계정에 `completedEpisodes`를 추가합니다. 기존 `seen`과19편 이야기의 계약은 유지합니다. 최초 미완료 응답의 기존 필드 모양도 보존합니다. 저장 실패 시 완료 행동을 기기에 남기고 다시 시도할 수 있습니다.

## 새 판과 기존 판 호환

엔진1.1.0/콘텐츠 `garden-2026.11.03-flow-v1`을 새 판에 사용합니다. 기존1.0.0 판과 로그는 그대로 재생합니다. 새 클라이언트는 시작 요청에 `engineVersion`을 명시하며 이전 버전도 이어할 수 있습니다. 버전이 없는 구형 클라이언트에는 `legacy-approved-v1.json`을 제공합니다. 구형 클라이언트가1.1 진행 판을 시작/이어하려 하면 추가 하트를 소비하기 전에 업데이트 안내로 차단합니다.

새200개 정의는7×7과8×8을 섞고, 좁은 분리 판은4종, 대다수는5종,6종은 후기의 넓은 전체 판에 제한합니다. 시작 선택지3개 이상과 무구매 승리 경로의 자동 섞기0회를 승인 기준으로 적용합니다. 런타임 솔버나 구매/패배 횟수 기반 난수 조정은 추가하지 않습니다.

1.1 섞기는 최대256개의 결정론적 순열에서 즉시 매치가 없고 가능한 수가3개 이상인 판을 찾습니다. 공간이 매우 제한되어 불가능한 경우 가장 선택지가 많은 합법 판으로 복구합니다.1.0의 첫 유효 순열/RNG 소비는 원래대로 유지합니다. 자동 섞기로 이동·하트를 추가 소비하지 않습니다.

## 로딩과 미술

첫 로딩은 기존 루미 초대장 일러스트를 화면 전체에 사용하고 하단에 실제 리소스 진행 바를 표시합니다. API 시작 대기는 기존 시작 화면을 유지하고 작은 루미 PNG 애니메이션과 준비 중 문구를 사용합니다. 가짜 서버 진행률이나 강제 대기 시간은 추가하지 않습니다.

새 배경/다리 모듈2장은 built-in image_gen으로 생성했습니다. 원본은 `packages/assets/source/rescue_bridge_*_v1.png`, 정확한 프롬프트·생성 원본·저장 경로·방법은 `packages/assets/prompts-rescue-v1.json`입니다. CSS는 배치/PNG 이동/투명도만 담당합니다. 다리와 캐릭터의 복원 단계는 실제 엔진 목표 상태에서 계산하고 보드 연출이 끝난 뒤 공개합니다. 구조 화면은 화면 크기에 맞는 고정 렌더링 표면과 내부 스크롤을 분리해, 넓은 브라우저에서 프레임이 게임 영역 밖으로 어긋나지 않도록 했습니다.

에셋 버전은 `garden-2026.11.03-story-v10`,162항목/atlas3/기존 애니메이션17종입니다. `loading-story.png`는 승인된 이야기 그림에서 복사하는 안정 부트스트랩 파일입니다. 이번 작업에서 네이티브 sync/설치나 운영 배포는 실행하지 않았습니다.

## 검증과 한계

- `output/rescue-v1/tests-serial.log`:26파일178검사 통과(병렬 worker를2개로 제한). 초기26동시 worker 검사에서 긴 재생2건의30초 timeout이 있었으며 타임아웃 기준을 완화하지 않고 재검증했습니다.
- `tests/flow-rescue.test.ts`:원래200개의1.0 승리 해시 전부 동일, 새 판200개 시작 선택지/무구매 경로/섞기 및 이야기 진행 복구 검사.
- `output/rescue-v1/bridge-proof.json`:실제 합법3행동으로 목표 단계0→1→2→3, 승리/이동15남음.
- `output/rescue-v1/api-http.json`:실제 격리 workerd/D1 HTTP 검사. 인증·해금·위조/부스터 입력 차단, 승리 재생·중복·동시 요청·계정 격리, Player와 진행 중 일반 판 불변, 구형 클라이언트 호환 확인. 기존 사용자 DB/세션에는 쓰지 않았습니다.
- `output/rescue-v1/flow-comparison.json`:동일한 무작위 선택 정책 seed3개×200맵=각600경로. 자동 섞기 구형596회/274경로 → 새48회/14경로. 서로 다른 판/진행 길이의 봇 표본이며 사람의 승률이나 실제 사용자 발생률이 아닙니다.
- 타입 검사와 별도 임시 출력 폴더의 웹 빌드 통과. 메인 작업의 dist/native 산출은 덮어쓰지 않았습니다.
- CUA 브라우저에서 일반 언어 선택, 새 일러스트 로딩 DOM, 첫 퍼즐 및 이후 레벨2 홈 진입을 관찰했습니다. 새 에피소드 전체의 실제 클릭/반응형 시각 검수는 반복된 CDP 연결 지연으로 완료하지 못했습니다. 테스트 세션의 직접 주입 방식은 자동 승인 검토에서 거부되었고 재시도/우회하지 않았습니다. 이후 일반 게스트 UI만 사용했습니다. 서버/엔진 검사와 브라우저 관찰 범위를 구별합니다. 임시 화면 크기를 복원하고 테스트 탭과 격리 서버를 정리했습니다.
