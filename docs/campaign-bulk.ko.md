# 1만 스테이지 단위 확장

현재 공개 범위는 1~10,000판이다. 기존 1~300판은 정의·실행 보드·레시피·승리 기록을 그대로 보존한다. 301~10,000판은 기존 18개 공략 유형을 재사용하고 수량·내구도·색·좌우 배치·시작 아이템을 조합한다. 콘텐츠 버전은 `garden-2026.11.04-bulk-v22`, 공통 엔진은 1.3.0이다.

1만 개의 서로 다른 기믹을 새로 만든다는 뜻은 아니다. 검증한 변형 보드와 각 판의 이동 예산을 연결해 1만 개의 플레이 가능한 스테이지를 제공한다. 신규 기믹은 이후 별도 소개·연습 구간과 함께 추가할 수 있다.

## 구성

- 기본 수집, 서리, 씨앗 배달, 색 화분, 이끼, 저장함, 상자 벽, 얼어붙은 온실, 특수 조합, 물관, 꽃봉오리, 회전 화분, 차양 및 이들의 복합 공략: 18개 유형.
- 301~1,000 / 1,001~3,000 / 3,001~6,000 / 6,001~10,000의 4개 강도 구간, 난이도 5종, 좌우 변형 2종: 총 720개 승인 변형.
- 강도에 따라 수집 목표, 장애물 내구도·수량, 물관 길이, 서리 겹수 등을 늘린다. 색 수집 목표 80, 상자 내구도 5, 일반 장치 내구도 8, 차양 충전 32, 서리 3겹 등의 상한을 둔다. 실제 판은 공간과 경로에 맞는 값만 적용한다.
- 10판마다 `쉬움 → 보통 → 보통 → 어려움 → 쉬움 → 보통 → 보통 → 매우 어려움 → 쉬움 → 연쇄 축제`를 유지한다. 연쇄 축제에는 무료 시작 특수 타일 3개가 있다.
- 자동 플레이 경로에 쉬움 +10 / 보통 +7 / 어려움 +4 / 매우 어려움 +2 / 축제 +12회 이상을 더하고, 판별로 0~2회를 추가한다. 후반에도 연속 고난도만 나오지 않는다.

숫자를 늘린 결과만으로 난이도가 정확히 결정되지는 않는다. 이 이동 여유는 제작 기준이며, 사람의 실패 원인·승률·아이템 사용 기록으로 조정해야 한다.

## 한 번에 추가하는 명령

```bash
npm run levels:bulk:build -- --to=10000
npm run levels:bulk:build -- --to=20000
npm run levels:bulk:build -- --to=30000
npm run levels:bulk:verify
```

이번에는 첫 번째 명령까지만 적용했다. 2만·3만은 다음 명령을 실행하면 기존 데이터를 보존하고 필요한 강도 구간의 변형을 추가한다. 기존 `levels:campaign:build -- --to=10000` 명령도 일괄 생성으로 연결한다. 50판마다 생성 규칙을 따로 작성할 필요가 없다.

생성 작업은 CPU 작업자 3개로 나눠 실행한다. 작업 중 승인한 변형은 `output/verification/bulk-v22-checkpoint.json`에 임시 저장해 재시작 시 재사용한다. 승리 경로가 없는 후보, 시작 자동 매치, 선택지 부족, 강제 섞기가 필요한 경로는 승인하지 않는다. 모든 공개 판을 실제 엔진으로 재생한 뒤에만 공개 범위를 갱신한다. 공개된 기존 판은 재생성하거나 덮어쓰지 않는다.

## 실행과 검증 자료

앱과 Worker는 승인 변형 보드와 작은 `[변형 번호, 이동 횟수]` 목록을 사용한다. 시작 시 보드 복사만 하며, 승리 경로 탐색이나 생성 재시도는 하지 않는다. 교환·폭발·장치 동작은 기존 로컬 엔진에서 실행한다. 승리 경로 JSON은 개발 검증용이며 앱 콘텐츠 모듈에서는 가져오지 않는다.

- `bulk-catalogue.json`: 승인 변형과 판별 연결 목록.
- `bulk-proofs.json`: 각 변형의 구매 없는 승리 경로와 각 판의 최종 상태 해시.
- `tests/fixtures/campaign-first300-hashes.json`: 기존 300판 보존 기준.
- `output/verification/bulk-v22.json`: 전체 재생 검사, 강도·완급·변형 통계.
- `/@fs/Users/kimkyutack/Desktop/puzzle-mobile/tools/campaign-v20-fixture.html?bulk=1&level=9998`: 로컬 Vite에서 실제 보드와 승리 경로를 확인하는 격리 페이지. 실제 계정·재화·API를 사용하지 않는다.

자동 승리 기록은 구매 없이 풀 수 있는 경로가 있다는 증거다. 사람의 난이도 평가나 운영 환경 검증을 대신하지 않는다. 운영 Worker 배포와 iOS/Android 설치본 갱신은 이 작업에 포함하지 않았다.

## 이번 확인 결과

- 1~10,000판 전체의 구매 없는 승리 기록 재생 통과. 승인 변형 720개, 장애물 배치·보드 구조 기준 130개 형태. 301~10,000판에는 쉬움 2,910판, 보통 3,880판, 어려움 970판, 매우 어려움 970판, 연쇄 축제 970판이 있다.
- 최초 300판 정의·실행 보드·레시피·승리 기록 해시 보존 및 기존 생성 레시피 재검증 통과.
- 전체 Vitest 43개 파일·297개 테스트, 타입 검사, 웹 프로덕션 빌드 통과. 큰 JS 청크에 대한 Vite 경고는 남아 있다. 승인 카탈로그는 원본 3,132,148바이트, gzip 241,331바이트다.
- 실제 Chrome의 격리 보드에서 9,998판 7수, 10,000판 9수로 승리 경로를 재현했다. 320×740에서 세 목표·이동 횟수, 9,009판의 네 목표(33/2/4/2)가 영역 안에 표시되고 수평 넘침이 없음을 확인했다. 10,000판은 390×844에서도 확인했다. 최종 검수 페이지의 오류 로그는 없었으며, 보드 재생성·뷰포트 변경 시 기존 Pixi 텍스처 해제 경고는 남아 있다.
- 화면과 관찰 결과는 `output/verification/campaign-bulk-browser/`에 보관했다. 운영 API·D1·실기기에서 실행했다는 의미는 아니다.
