# 3만 레벨 캠페인 — v20

## 구현 범위

캠페인은 최대 30,000레벨, 50레벨씩 600개 묶음으로 계획한다. 수작업 규칙을 등록한 최초 구간은 1~300레벨이다. 이후 사용자의 일괄 확장 요청에 따라 기존 공략의 수량·횟수·배치를 변형하는 방식으로 1~10,000판을 공개했다. 현재 생성·검증 방법과 다음 1만 판 추가 명령은 [1만 판 단위 확장](campaign-bulk.ko.md)을 참고한다. 아래 300판 용량과 50판 제작 절차는 초기 버전 기록이다.

기존 1~200판의 배치와 첫 튜토리얼을 유지하고 이동 여유 및 난이도 흐름을 조정했다. 새 규칙의 첫 구간은 201~250판이다. 첫 세 판은 소개 1판과 연습 2판이며, 소개·연습 판은 자동 플레이에서도 최소 두 번의 조작을 경험해야 검증을 통과한다.

| 첫 등장 | 규칙 | 동작 |
|---|---|---|
| 201 | 접이식 물관 | 주변 매치·직접 타격 1회마다 점유 칸 하나가 사라지며 열린 칸에 타일이 공급된다. 한 효과가 여러 칸을 맞춰도 해당 물관에는 1회만 적용된다. |
| 211 | 씨앗 꽃봉오리 | 주변에서 표시된 색을 맞춰 충전한다. 열린 꽃에서 나온 씨앗을 출구까지 내려보내야 완료된다. 망치로 색 조건을 건너뛸 수 없다. |
| 221 | 회전 화분대 | 이동을 소비하는 조작 후 정해진 경로를 따라 한 칸 이동한다. 유료 도구·섞기는 이동을 유발하지 않는다. 막힌 칸·서리·출구·씨앗으로 이동하지 않으며 자리를 바꾸는 일반 타일의 식별자를 보존한다. |
| 231 | 온실 차양 | 지정된 색의 매치에서 모인 블록 수만큼 충전된다. 완충되면 점유 영역이 열리고 타일이 내려온다. |

6번째 묶음 251~300판에는 새 기믹을 조합한 다섯 공략 유형을 추가했다. 자세한 구성과 검증 범위는 [다음 50판 제작 기록](campaign-pack6.ko.md)을 참고한다.

## 난이도 흐름

일반 10판의 흐름은 쉬움 → 보통 → 보통 → 어려움 → 쉬움 → 보통 → 보통 → 매우 어려움 → 쉬움 → 연쇄 축제다. 새 규칙의 첫 3판에서는 소개·연습이 이 주기를 우선한다. 연쇄 축제의 새 보드에는 시작 특수 타일이 포함되며 인벤토리를 차감하지 않는다.

현재 자동 플레이의 클리어 이동 수에 소개 +14, 연습 +12, 쉬움 +10, 보통 +7, 어려움 +4, 매우 어려움 +2, 축제 +12의 여유를 준다. 이 수치는 제작 기준이며 사람의 승률이 아니다. 사람의 반복 도전·실패 원인·아이템 사용 기록에 따라 재조정해야 한다.

진행 구간은 1~100 기본 학습, 101~1,000 주요 규칙과 조합, 1,001~5,000 공략 순서, 5,001~10,000 구역·경로 조합, 10,001~30,000 신규 규칙과 재구성으로 나뉜다. 후반에도 새 규칙의 첫 등장은 쉬운 소개·연습으로 제작한다. 아직 구현하지 않은 새 기믹의 등장 레벨을 제작 완료 데이터에 미리 기록하지 않는다.

## 용량과 실행 구조

실제 앱과 Worker는 3만 판의 전체 보드 JSON을 포함하지 않는다. 기존 버전의 고정 콘텐츠와 검증된 판의 작은 `[생성 시도 번호, 이동 횟수]` 레시피를 포함한다. 현재 300판 레시피는 2,101바이트이며 전체 보드와 승리 기록은 개발 검증용 파일에 보관된다.

판을 시작할 때 승인된 고정 시드로 보드를 결정적으로 복원한다. 시작 요청 중 승리 경로 탐색이나 다른 시드 재시도는 하지 않는다. 이동·폭발·물관 수축·화분 이동은 공통 TypeScript 엔진으로 로컬에서 계산하고 서버는 같은 규칙으로 행동을 검증한다.

## 추가 제작과 공개

- `npm run levels:campaign:build`: 현재 승인된 300판을 보존하고 다시 검증한다. 다음 묶음은 기획·전용 생성 규칙을 등록한 뒤 `--to=350`으로 확장한다.
- `npm run levels:campaign:verify`: 현재 승인된 모든 판의 시작 상태·중복·레시피 복원·승리 기록을 재검증한다.
- 레벨 번호 상한은 30,000이다. 아직 기획·등록하지 않은 묶음은 생성 명령에서도 거절하며, 운영에서는 새 묶음을 등록해 50판씩 제작·검수한다.
- 신규 기믹은 계약·공통 엔진·이미지·설명·소개/연습 판·동작 테스트를 함께 추가한다. 단순한 색 교체나 시드 변경만으로 장기 다양성이 확보됐다고 판단하지 않는다.
- `--rebuild`는 미공개 초안 재제작용이다. 이미 공개한 판에는 사용하지 않는다. 규칙 또는 복원 방식이 바뀌면 새 엔진·콘텐츠 버전으로 분리한다.

도구 없는 승리 기록, 초기 자동 매치 없음, 시작 선택지 3개 이상, 강제 섞기 없는 클리어, 중복 보드 없음, 레시피 복원 일치가 모두 확인된 뒤 파일을 저장한다. 봇이 풀지 못한 후보는 불가능으로 단정하지 않고 미승인으로 남긴다.

## 호환성과 배포

새 엔진은 1.3.0이다. 1.0.0 / 1.1.0 / 1.2.0의 저장된 판을 계속 재생하며 1.2.0 클라이언트에는 기존 콘텐츠를 제공한다. 새 기믹은 이전 엔진으로 전달하지 않는다. 서버가 1.3.0 요청을 지원하도록 배포한 후 새 앱을 배포해야 한다.

이번 작업은 로컬 소스·리소스·웹 빌드 검증이다. 운영 Worker 배포, 원격 DB 변경, iOS/Android 설치본 갱신은 수행하지 않았다. 미공개 구간의 API는 `CONTENT_NOT_READY`를 반환하고 시작 모달은 다음 업데이트 안내를 표시한다.

## 미술과 검증 자료

새 장애물 PNG 4종은 built-in image_gen으로 생성했다. 원본과 정확한 프롬프트는 `packages/assets/campaign-v20.json`에 기록했다. 소스는 `packages/assets/source/mechanic_*_v20.png`이며 기존 서리·덩굴 아트를 대체하지 않는다. 물관은 칸 단위로 그려 남은 길이가 실제 보드 점유 칸과 일치하며, 회전 화분은 이동 후 위치로 320ms 동안 이동한다.

검증 보고서는 `output/verification/campaign-v20.json`, 격리된 렌더링 검수 페이지는 `tools/campaign-v20-fixture.html`이다. 이 페이지는 실제 공통 엔진·보드·이미지를 사용하고 인증·API·재화 변경을 차단한다.

## 초기 250판 검증 기록

- 전체 Vitest 41개 파일, 285개 테스트 통과. 타입 검사와 웹 프로덕션 빌드 통과.
- 250판 모두 유료 도구 없는 승리 기록 재생, 초기 선택지·중복·저장된 레시피 일치 검증 통과.
- 시작 API의 1.3/1.2 협상, 로컬 계산과 초기 상태 일치, 251판 미공개 응답 및 원장 쓰기 없음은 모의 트랜잭션 단위 테스트로 확인했다. 운영 D1에서 이 기능을 실행했다는 의미가 아니다.
- Wrangler 운영 설정의 `deploy --dry-run` 패키징 통과(실제 업로드 없음).
- Chrome의 격리된 실제 렌더링 페이지에서 201판 2수, 211판 8수, 221판 2수, 231판 3수로 직접 버튼 조작해 클리어를 확인했다. 이는 봇 증명 경로를 화면에서 재현한 것이며 사람 난이도 검수는 아니다.
- 390×844 및 320×740 화면을 확인했다. 320px 다중 목표 숫자·이동 숫자가 각 영역 안에 있고 수평 넘침이 없음을 DOM 경계와 화면으로 확인했다.
- 목표 아이콘의 조건식 우선순위 문제와 한 줄 차양의 nine-slice 높이 단위 문제를 화면 검수 중 수정했다.
- 화면·단계 기록: `output/verification/campaign-v20-browser/`. 최종 차양 화면은 `curtain-390.jpg`, 좁은 화면의 세 목표는 `bud-320.jpg`다. 실제 iOS/Android 설치본 검수는 수행하지 않았다.
