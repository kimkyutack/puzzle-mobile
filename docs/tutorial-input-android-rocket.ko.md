# 튜토리얼 이후 입력과 안드로이드 시스템 영역

## 입력 정지 경로

앱은 교환을 계산한 직후 입력을 잠그고, 보드의 연출 종료 신호로 해제한다. 그런데 보드가 다시 마운트되거나 크기 변경 때문에 최종 상태를 애니메이션 없이 그리면, 보드 내부의 연출 플래그가 꺼져 있다는 이유로 종료 신호가 생략될 수 있었다. 이때 보드는 idle이지만 앱의 잠금만 남아 유효 교환도 시각적으로 되돌아온다.

- 새 상태·이벤트는 `useLayoutEffect`에서 크기 검사 ticker보다 먼저 반영한다.
- 크기 변경에서도 아직 소비하지 않은 새 이벤트는 연출한다.
- 애니메이션 없이 최종 보드를 표시한 경우에도 종료 신호를 보낸다.
- 판 ID별로 보드 인스턴스를 분리하고, 지난 판의 콜백이 새 판의 잠금을 변경하지 못하게 한다.
- 입력 중복 방지 플래그는 동기 계산의 `finally`에서 해제하며, 연출 잠금은 별도로 유지한다.
- 늦은 `/me` 결과는 현재 판 ID, 확정 sequence, 종료 상태, 미저장 입력을 확인한 뒤에만 보드에 반영한다.

완료한 안내의 로컬 기록은 계속 유지한다. 2레벨의 로켓 만들기는 1레벨 교환 안내와 다른 학습 단계이며, 새로운 특수 아이템의 첫 등장 안내도 유지한다.

## 안드로이드

Android만 초기 viewport hint와 HTML viewport를 `contain`으로 맞춘다. Capacitor 8 SystemBars가 구형·신형 WebView 모두에서 WebView 바깥에 시스템바/노치 공간을 예약한다. 따라서 헤더 이미지, 배경, 팝업도 상태바와 내비게이션 영역을 침범하지 않는다. 기존 CSS inset은 native padding 경로에서 0이 되어 이중 여백이 생기지 않는다. 예약 영역은 기존 네이티브 배경색과 밝은 시스템 아이콘을 사용한다.

iOS와 웹은 기존 `viewport-fit=cover` 및 CSS safe-area 처리를 유지한다. 이 변경은 네이티브 빌드를 하지 않았으므로 안드로이드 실기기 적용 결과는 아직 확인하지 않았다.

## 로켓 규칙과 검증 범위

1.4.0 이상으로 유지되는 새 규칙에서 가로 4개 → 세로 로켓, 세로 4개 → 가로 로켓을 적용한다. 1.0–1.3의 저장 판은 기존 규칙으로 재생한다. 새 번호가 추가되어도 버전별 판의 계산을 바꾸지 않는다.

- 타입 검사 통과.
- 전체 단위 검사: 61개 파일, 417개 테스트 통과. 기존 카탈로그의 승리 로그와 해시는 해당 규칙 1.3으로 명시해 계속 검증한다.
- 실제 App/Board를 사용한 격리 브라우저 검사: 2레벨 시작 → 첫 교환 → 첫 등장 안내 닫기 → 이전 sequence의 지연 응답 전달 → 두 번째 교환 → 정원 왕복 → 이어하기 → 세 번째 교환 → 2레벨 클리어. 서버 재생 거절 0건, sequence 3, 정상 보상 확정.
- 별도 보드 재표시 재현: 수정 전에는 보드 idle / 앱 guard=true / barrier=true이며 다음 유효 입력도 turn=1에 멈췄다. 수정 후에는 같은 경로에서 guard와 barrier가 해제되고 다음 입력이 turn=2로 진행한다.
- `tests/rocket-direction.test.ts`는 버전별 방향, 생성 위치, 실제 세로 발사, 결정적 재생을 검증한다.
- `tools/verify-rocket-rules.ts`는 별도 보조 봇 탐색이다. 두 greedy 정책이 승리 로그를 찾지 못했다는 결과는 불가능한 맵이라는 증명이 아니며, 전체 신규 규칙 맵의 인증 완료로 해석하지 않는다. 기존 이동 횟수·목표·배치는 이 검사 때문에 조정하지 않는다. 이번 1.4 검사에서는 1,380개 보드/템플릿 중 1,285개에서 승리 로그를 찾았고 95개는 두 정책으로 증명하지 못했다. 따라서 전체 새 규칙 카탈로그의 클리어 경로 재인증은 완료되지 않았다.

증거는 `output/verification/tutorial-input/`에 보관한다. 앱/Worker/native 빌드, 배포, native sync, Git push는 수행하지 않았다. 브라우저 검사는 임시 클라이언트 소스 복사본의 Vite 개발 서버, 작업공간의 공통 패키지, 가짜 API를 사용했다. 운영 API에는 요청하지 않았다.
