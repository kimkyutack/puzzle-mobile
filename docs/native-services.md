# Native services and provider configuration

The native projects are `android/` and `ios/App/`. Their provisional application identifier is `com.cloudgarden.match`; the working name is not a trademark-cleared release name. Capacitor configuration is JSON because the currently installed TypeScript 7 no longer exports the compiler API used by Capacitor's TypeScript configuration loader on Node 22.14. No credentials or signing identity are committed.

## Local and native operation

Run `npm ci`, build the web client, then `npx cap sync`. Run `npx cap open android` or `npx cap open ios`. The browser uses the local API proxy. A packaged app requires `VITE_API_URL=https://<your-worker-domain>/api` at build time; a relative `/api` points to its local asset origin and cannot reach Workers. Rebuild and sync after changing public environment variables.

For a locally playable debug package, keep `npm run dev:api` running and use `node tools/native-build.mjs local`. This builds and syncs a bundle whose API is `http://localhost:8787/api`; ads and store purchases are disabled in this local bundle. On Android run `adb reverse tcp:8787 tcp:8787` before launching the installed debug APK. Repeat this after disconnecting/restarting the device or emulator. On the iOS Simulator, `localhost` is the Mac running Wrangler. A physical iPhone needs a reachable HTTPS API and its own signing profile instead.

Android's HTTP permission and loopback network-security policy exist only in `src/debug`; mixed-content allowance is gated by the package's debuggable flag. iOS uses `Info.Debug.plist` for the local exception, while Release uses the normal plist with no ATS exception. Release packaging additionally rejects local or missing build metadata. To prepare a release bundle, run `VITE_API_URL=https://<your-worker-domain>/api node tools/native-build.mjs release`. `native-build.json` records the public endpoint and build mode so Gradle/Xcode can reject an accidentally reused local bundle. This does not deploy Workers or supply a signing identity.

`tokenStorage` uses Keychain/Android Keystore on native platforms. A native secure-storage failure does not fall back to localStorage. The browser development session uses localStorage and is not advertised as secure native storage. The server owns progress and currency; these values are not entrusted to this cache. Android device backup is disabled to avoid copying encrypted session blobs without their keys. Signing out and deleting an account must clear the stored session.

Session writes are serialized so delayed secure-storage writes cannot replace a newer account. `installSession` and `clearSession` invalidate in-flight requests before asynchronous storage operations; refresh retries preserve the original request body and idempotency key. An old-account request is never retried under a newly selected account.

Native plugin versions are exact in package-lock: Capacitor 8.6.0, AdMob 8.3.0, social login 8.7.5, secure storage 0.13.0, native purchases 8.9.6. SDK compatibility was checked against package types and source. The platform SDKs still require device and store sandbox checks; a successful TypeScript test is not such a check.

## Google and Apple identity

The app requests a session-bound challenge from `POST /api/auth/challenge`, passes the server nonce to the platform SDK, then submits to `POST /api/auth/link`. The Worker uses `jose` with the provider's remote JWKS and checks allowed algorithms, issuer, configured audiences, expiry, nonce and subject. Email is not an account key. The server consumes each challenge only once and handles existing-account conflicts without merging balances.

- Public build variables: `VITE_GOOGLE_WEB_CLIENT_ID`, `VITE_GOOGLE_IOS_CLIENT_ID`, `VITE_APPLE_SERVICE_ID`, `VITE_APPLE_REDIRECT_URL`.
- Worker audience configuration: `GOOGLE_CLIENT_IDS`, `APPLE_CLIENT_IDS`, comma-separated explicit allowed audiences.
- Google Android requires an OAuth Android client for `com.cloudgarden.match` and each installed signing certificate's SHA-1, in the same Cloud project as the Web client. The Android client ID is not the Web client ID.
- Google iOS requires an iOS OAuth client and `GOOGLE_REVERSED_CLIENT_ID` Xcode build setting matching its reverse URL scheme. SceneDelegate forwards Google callback URLs to GoogleSignIn.
- Apple iOS has a Sign in with Apple entitlement. A developer team/provisioning profile supporting that entitlement is needed for a signed device build.
- Apple Android uses the official HTTPS authorization page in the system browser. It does not use the social plugin's legacy client-secret mode. Apple posts the code and state to `POST /api/auth/apple/callback`. The Worker exchanges it, verifies the nonce, and stores the verified subject against the challenge. The fixed `cloudgarden://auth` redirect contains only opaque state and a success indicator. It never carries tokens or client secrets. The app then completes linking using its authenticated session and challenge ID. Persisted pending challenge state supports retry after returning to the app.
- Apple Android callback settings: `APPLE_TEAM_ID`, `APPLE_AUTH_KEY_ID`, `APPLE_AUTH_PRIVATE_KEY` (Workers secret), `APPLE_AUTH_CLIENT_ID`, `APPLE_AUTH_REDIRECT_URL`. Configure the HTTPS return URL and domain in the Apple Services ID.

Apple native login also sends its one-use authorization code to Workers. The code is exchanged using `APPLE_BUNDLE_ID` with no redirect URI; the web/Android flow uses the Services ID and its configured return URL. The exchanged ID token is checked again against the exact redeeming client and server nonce. The refresh token is encrypted with `jose` compact JWE (`dir` + `A256GCM`) before D1 storage or revocation outbox insertion. `AUTH_TOKEN_ENCRYPTION_KEY` must be 32 random bytes encoded as unpadded base64url and stored as a Workers secret. Rotate this key with a migration plan: replacing it without re-encrypting retained ciphertext makes pending revocations unreadable.

Account deletion schedules the encrypted authorization for Apple's official `/auth/revoke` endpoint. Only HTTP 200 completes that operation; Apple also returns 200 for an already revoked token, allowing safe retry. Provider secrets, raw refresh tokens, and authorization codes are never written to public assets or logs. Configure `/api/auth/apple/notifications` as the separate Sign in with Apple identity notification URL for `consent-revoked` and `account-deleted`; this uses the Apple identity JWKS and is distinct from App Store Server Notifications. The verifier checks issuer, configured audience, signature, issue/event times and event ID. See [Apple account deletion guidance](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion), [token revocation](https://developer.apple.com/documentation/signinwithapplerestapi/revoke-tokens), and [identity account notifications](https://developer.apple.com/documentation/signinwithapple/processing-changes-for-sign-in-with-apple-accounts).

The identity controls use the official Google button PNGs and Apple's Korean Continue button image, separated from generated game art. Their source URLs are in `apps/client/public/provider-assets/SOURCES.md`. The native OAuth provider still needs configured client IDs and a signed device build; the presence of the button is not evidence of successful live login.

Reference: [Google ID verification](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token), [social login native setup](https://github.com/Cap-go/capacitor-social-login), [Apple authentication documentation](https://developer.apple.com/documentation/signinwithapple).

## Optional rewarded ads

Only `rewardedAds.show()` exists in the app integration; there are no banner, interstitial or app-open calls. It requires a player action and a server-created intent. Before loading a new ad, it requests UMP consent information, presents the official form when required and checks `canRequestAds`. Privacy options use the SDK's form. Declining consent does not block gameplay or base rewards.

The intent ID is passed as `ssv.customData` and the original account ID as `ssv.userId` before `prepareRewardVideoAd`. The SDK's reward event moves UI to `pending`; it does not award anything. The app must poll the server's intent status. Dismissal is not proof of a reward, and a late SSV can still settle an earlier intent. The audio pause/resume events are `garden:audio-pause` and `garden:audio-resume`.

AdMob callback verification keeps the exact original query bytes before `&signature=...&key_id=...`. Node's standard crypto implementation verifies ECDSA P-256/SHA-256 ASN.1 DER signatures. Public keys are fetched only from Google's fixed verifier endpoint, cached for six hours, and refreshed immediately on an unknown key. Duplicate fields, unknown ad units, wrong reward type/amount, invalid signatures and future signed times are rejected. An old arrival alone is not rejected; the server compares signed view time with the original intent validity interval. The callback return contract uses milliseconds.

Set each AdMob unit to `reward_amount=1` and `reward_item=reward`. The server intent determines the actual game currency amount. `ADMOB_AD_UNITS` is the explicit comma-separated allowlist; `ADMOB_REWARD_ITEMS=reward`. Configure the public SSV callback URL in AdMob, and configure consent/privacy messages there. Public client flags are `VITE_ENABLE_ADS=true` and `VITE_ADS_TEST_MODE=true` for SDK testing. Production activation also requires real ad units, regional consent review and device verification.

The Android string resource and iOS plist currently contain Google's **official sample app IDs**. They must be replaced before production release; they are not working project credentials. The iOS plist includes Google's SKAdNetwork identifier; add the full current list for any enabled mediation networks. No live ad was shown or monetized in this task.

Reference: [AdMob SSV and retries](https://developers.google.com/admob/android/ssv), [native rewarded/SSV plugin](https://github.com/capacitor-community/admob/blob/main/docs/rewarded.md), [UMP privacy](https://developers.google.com/admob/ios/privacy).

## Store purchases

The UI catalog has quantities, but prices are taken only from `NativePurchases.getProducts().priceString`. No web payment replacement is provided. Native purchases are disabled until `VITE_ENABLE_PURCHASES=true`; the browser never invokes the plugin's mock purchasing behavior.

`autoFinishTransactions` is false both in Capacitor configuration and at runtime, including recovery. `purchaseProduct` also disables automatic acknowledgement. Before showing a store sheet, `/purchases/prepare` reserves a purchase intent and pins the season. The app persists its opaque ID before the native call. Google receives `SHA256(server userId + ":" + purchaseIntentId)` as its obfuscated account ID; Apple receives the intent UUID as its appAccountToken. The Worker verifies this exact receipt-to-intent binding and the intent owner. Quantity is fixed to one. Definite cancellation releases the reservation; network failure and pending approval retain recoverable state.

Google verification uses `purchases.productsv2.getproductpurchasev2`, a service-account OAuth token with the Android Publisher scope, exact package/product/account checks and explicit PURCHASED/PENDING/CANCELLED handling. The purchase token is the unique transaction key; an order ID is not. Only after D1 grant commit does the server consume or acknowledge. Failures must remain in the outbox for retry. A repeated finish checks the actual consumption/acknowledgement state. RTDN verifies the Pub/Sub OIDC bearer audience and sender email before interpreting a notification.

Completed purchases require a valid provider completion timestamp. The Google consumption enum is `CONSUMPTION_STATE_CONSUMED`; already consumed purchases cannot create a fresh grant, and a zero refundable quantity is treated as cancelled. Sandbox receipts are rejected by a Production-configured verifier and vice versa.

Apple verification uses Apple's official `SignedDataVerifier` for the submitted JWS, fetches current transaction information from the selected App Store Server API environment, and verifies that signed result again. Bundle/environment/account/product/quantity and revocation are checked. Notification signatures are verified with the same library. Apple has no server finish endpoint: the client finishes the StoreKit transaction only after a committed grant response. `getUnfinishedTransactions` supports recovery; a repeated receipt cannot create a new balance through the server uniqueness rules.

Both native SDKs can report deferred approval without returning a transaction. The app signals `/purchases/intents/:id/pending` without awarding anything. Android recovery uses `getPurchases(INAPP)` because the plugin's unfinished query excludes pending purchases; returned tokens are reverified by the Worker. Apple recovery uses unfinished StoreKit transactions after approval. Recovery resolves the exact receipt binding on the server, rather than assigning an older receipt to a newer local reservation for the same SKU. Store operations are serialized around the plugin's single BillingClient.

Settings lists `/purchases/intents` and offers synchronization. A two-step cleanup is available only for a server-designated `reserved` request; it does not refund or revoke a completed payment. `pending` and `review` requests remain visible and cannot be dismissed as if approval had never happened. No time-based expiry silently drops an outstanding deferred purchase.

Worker settings/secrets:

- `GOOGLE_PACKAGE_NAME`, `GOOGLE_IAP_ENVIRONMENT=Sandbox|Production`, `GOOGLE_SERVICE_ACCOUNT_JSON` (secret), `GOOGLE_RTDN_AUDIENCE`, `GOOGLE_RTDN_EMAIL`.
- `APPLE_BUNDLE_ID`, `APPLE_APP_ID` (required in Production), `APPLE_IAP_ISSUER_ID`, `APPLE_IAP_KEY_ID`, `APPLE_IAP_PRIVATE_KEY` (secret), `APPLE_IAP_ENVIRONMENT=Sandbox|Production`.
- `APPLE_ROOT_CA_PEMS` is an optional operator override. The three official public Apple root certificates downloaded from [Apple PKI](https://www.apple.com/certificateauthority/) on 2026-11-02 are bundled in `apps/api/src/providers/certs`; subjects, expiry dates and SHA-256 fingerprints are recorded in its manifest. The verifier never accepts a client-supplied trust anchor. Online certificate checks are enabled. Configure App Store Server Notifications with the correct environment URL.

Register all product IDs from `packages/content` in both store consoles. Register the repeatable season-pass SKU as a consumable one-time purchase; D1 owns the nonrenewing season entitlement. Consuming the store transaction after a grant allows the next season to use the same SKU. Starter pack ownership is permanent and server-limited to one purchase. Pending or cancelled purchases do not grant. Restore synchronizes server balances/entitlements and pending transactions; it does not replenish spent consumables.

Reference: [Google billing security](https://developer.android.com/google/play/billing/security), [ProductPurchaseV2](https://developers.google.com/android-publisher/api-ref/rest/v3/purchases.productsv2), [Apple server library](https://github.com/apple/app-store-server-library-node), [native purchase manual finishing](https://github.com/Cap-go/capacitor-native-purchases).
