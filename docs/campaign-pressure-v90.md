# 전체 캠페인 난이도 상향 v90

2026-11-23 · 로컬 적용 및 검증 완료. 운영 배포/네이티브 동기화는 이 작업에 포함하지 않았다.

## 적용 범위

실제 공개된 1~20,000레벨을 검사했다. 1~30레벨의 기본 학습과 새 방식의 첫 소개판 18개를 보존하고, 나머지 **19,952개**에 난이도를 적용한다. 31~49는 완만한 준비 구간이고, 50부터 장애물의 양·겹수와 이동 제한을 함께 강화한다. 미공개 20,001 이후를 새로 공개하지 않는다.

최종 게시 단계 `campaignPressureLevel`에서 적용하므로 이전 생성기의 최소 23회 보장이나 `Math.max(source.moves, ...)`가 상향을 되돌리지 않는다. 진행 구간의 증가율은 100레벨 단위 검증점을 포함한 연속 곡선으로 계산한다. 일반/어려움/매우 어려움은 장애물 밀집도·강화 비율·이동 여유가 서로 다르다. 개별 판의 방식과 난이도 리듬, 새 방식 첫 소개판의 예외는 유지한다. 서로 다른 모든 판의 절대 난이도가 직전 판보다 높다는 의미는 아니다.

## 변경

- 기존 장애물의 연결된 구역을 넓히고, 타일을 맞출 공간과 보충 경로는 확보한다. 그림과 공격 규칙은 그대로 사용한다.
- 장애물 겹수, 상자 내부 장애물, 서리 겹수를 증가시킨다. 실제 보드와 목표 개수도 함께 갱신한다.
- 풍차/원반 발사기/공성 장치의 탄약과 연결 관계를 보존한다. 원격 목표만 강하게 만들어 탄약이 부족해지는 변경은 금지한다.
- 물길/동물 길은 50부터 여러 행에 걸친 경로와 분산된 흙마개로 바꾼다. 50부터 5색, 200부터 6색으로 짧은 자동 연쇄 클리어를 줄인다. 기존 매치·아이템 공격 규칙을 사용한다.
- 연승 선물, 강화 무지개등, 아이템 성능/보상/가격은 바꾸지 않는다. 보상을 받은 사람만 더 어려운 판을 주는 방식도 사용하지 않는다.
- 새 판의 콘텐츠 버전/해시가 변경된다. 이미 저장된 `Run.level`과 재개·이어하기는 교체하지 않는다. 1.28 이하의 보존 규칙에는 이번 조정을 적용하지 않는다.
- 골드 보너스판에는 적용하지 않는다.

## 전후 예시

| 레벨 | 이동 횟수 | 실제 장애물 수 | 외부/내부 겹수 합계 또는 흙마개 |
|---|---|---|---|
| 50 | 22 → 10 | 물길 | 흙마개 3 → 21 |
| 54 | 22 → 17 | 8 → 24 | 11 → 54 |
| 107 | 19 → 15 | 9 → 21 | 15 → 46 |
| 554 | 23 → 16 | 18 → 32 | 36 → 87 |
| 557 | 36 → 27 | 39 유지 | 50 → 70 |
| 558 | 23 → 14 | 18 → 37 | 36 → 107 |
| 19,998 | 49 → 26 | 32 유지 | 이미 최대 겹수인 96 유지 |

겹수 합계는 구조적 작업량 지표다. 한 번의 매치/아이템이 여러 장애물을 타격하므로 필요한 이동 횟수와 같지 않다.

## 검증 결과

1. 전체 20,000판에서 `validateLevel`, 실제 `createGame`, 목표 일치와 보충 경로 검사: 오류 0. 기존 대비 약해진 장애물 겹수 없음. 첫 소개판 이외의 50 이상 판에 조정 적용 확인.
2. 50~19,998의 대표 30레벨에서 시작 도구 없음 / 연승 선물 / 연승+가능 구간 강화 무지개등으로 전후 플레이. 추가 경로 3시드와 시작 도구 3종 조합을 포함해 **258회**를 끝까지 시뮬레이션하고 모든 입력 로그를 재생하여 상태 해시 일치 확인.
3. 같은 자동 정책의 대표 30판 결과: 시작 보너스 없음 27승→10승, 연승 선물 30승→18승, 연승+가능 구간 강화 상태 29승→20승. 200 미만에서는 실제 게임과 동일하게 강화 무지개등을 켜지 않는다. 이는 자동 정책의 표본 결과이며 사람의 승률이나 전체 레벨의 무도구 클리어 가능성을 입증한 수치가 아니다.
4. 실제 Chrome 게임 화면에서 프로덕션 `CascadeBoard`/`PlayHud`, 전체 애니메이션과 보드 포인터 입력으로 4판 완주. 각 결과가 별도 엔진 기록과 정확히 일치한다.
   - 50, 시작 선물 없음: 10회 중 9회로 승리, 1회 남음.
   - 557, 연승 선물 4개+강화 무지개등: 27회 중 22회로 승리, 5회 남음.
   - 558, 같은 강화 상태: 14회 소진 후 목표가 남아 실패.
   - 554, 연승+강화+시작 도구 3종: 16회 중 8회로 승리.
5. 추가 도구 검증: 58/98의 실패 경로에서 종료 직전 망치 1개를 사용하면 클리어되는 실제 입력 경로와 해시를 확인했다. 별도 실패 사례 7개에서도 화면 전체 공격 도구 1~2개를 사용한 성공 경로를 확인했다. 도구 추가는 검증용 로컬 시뮬레이션이며 실제 계정/인벤토리를 차감하지 않았다.
6. 관련 18개 테스트 파일 **166개 통과**, `npm run build` 통과, 운영 설정 Worker `--dry-run` 패키징 통과. 업로드/배포는 하지 않았다.

브라우저 검증은 격리된 로컬 렌더러이며 서버 API와 실제 계정 쓰기를 막았다. 새 판 시작, 저장 판 재개, 콘텐츠 해시, 연승/강화 상태, 인벤토리 차감과 중복 지급은 별도의 API 통합 테스트로 확인했다. 모든 20,000판을 브라우저로 직접 완주하거나 사람 대상으로 플레이 테스트한 것은 아니다.

```sh
node --import tsx tools/level-validation/campaign-pressure-audit.ts --scan
node --import tsx tools/level-validation/campaign-pressure-audit.ts --levels=50,51,54,58,60,78,98,107,154,198 --out=early-play
node --import tsx tools/level-validation/campaign-pressure-audit.ts --levels=254,357,458,554,557,558,812,924,1038,1148 --out=mid-play
node --import tsx tools/level-validation/campaign-pressure-audit.ts --levels=1304,1458,1616,1718,1828,2054,4058,6054,12054,19998 --out=late-play
node --import tsx tools/level-validation/campaign-pressure-audit.ts --levels=50,60,550 --seeds=92347,173891,891733 --out=routes-play
node --import tsx tools/level-validation/campaign-pressure-audit.ts --levels=54,58,98,198,254,458,554,558,1148,1458,4058,19998 --modes=stocked --seeds=92347,173891 --after-only --out=stocked-play
```

결과는 `output/verification/campaign-pressure-v90/`에 저장한다.

- `publication.json`: 전체 레벨의 전후 수치와 구조 검사.
- `*-play.json`: 시작 판, 시작 보너스, 전체 입력, 최종 해시.
- `browser.json` / `browser-proof.jpg`: 실제 화면 입력 결과와 이미지.
- `hammer-rescue.json` / `tool-rescue.json`: 추가 도구를 사용한 성공 경로.
- `final-tests.log` / `build.log` / `worker-build.log`: 검증 로그.

변경 전 게시 함수 스냅샷도 같은 결과 폴더에 저장한다. 이 변경의 전후를 재현할 때는 해당 파일을 보존해야 한다. 삭제하면 다음 감사 실행 시 그때의 콘텐츠 생성기로 비교 기준을 다시 만든다.
