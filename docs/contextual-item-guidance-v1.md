# 루미의 상황별 아이템 안내

1~100레벨의 일반 스테이지에서 실제 타일 배치를 검사하고, 아직 만들기를 배우지 않은 아이템을 만들 수 있는 이동이 있으면 루미가 안내한다. 2레벨을 모든 아이템을 연습하는 고정판으로 바꾸지 않는다. 기존 레벨 데이터, 리필 규칙, 엔진 버전과 서버 판정은 유지한다.

- 101레벨부터는 생성 안내와 미완료된 사용 안내를 모두 표시하지 않는다.
- 첫 정원 복구와 스토리가 끝나면 루미가 실제 다음 퍼즐로 안내한다.
- 로켓(가로·세로 공통), 씨앗비행기, 꽃폭탄, 무지개등, 꿀벌집의 최초 생성 기회를 찾는다.
- 실제 게임 엔진으로 해당 이동이 아이템을 만드는지 확인한다. 배치를 바꾸거나 아이템을 주입하지 않는다.
- 이동할 두 칸과 완성될 모양만 밝게 표시한다. 루미 말풍선과 손가락으로 이동을 안내한다.
- 생성 후 실제 아이템 위치를 찾아 사용을 안내한다. 배운 기록은 기존 도움말 저장·동기화 경로에 저장한다.
- 기존 아이콘 발견 도움말과 생성 학습 이력은 구분한다. 시작 선물로 아이콘을 이미 봤더라도 만드는 방법은 안내한다.
- 보너스판과 별도 장치 조작판은 해당 판의 조작 안내를 우선한다. 첫 판의 기본 3매치 안내도 우선한다.

주요 코드: `apps/client/src/item-guidance.ts`, `ItemLessonGuide.tsx`, `item-lesson.css`, `App.tsx`, `Board.tsx`, `locales/item-lesson.ts`.

보드 강조는 보드의 실제 geometry 크기를 사용한다. 7열 보드가 9열 기준 호스트보다 좁게 렌더링될 때에도 강조 영역과 실제 타일이 일치한다. 강조 오버레이와 손가락은 같은 Pixi 장면에 배치하며, 손가락은 오버레이 위의 마지막 레이어에서 그린다. 같은 이유로 포인터 좌표와 드래그 배율을 호스트의 실제 CSS 크기에 맞춰, 보이는 타일 위치에 대한 터치가 일치하도록 했다.

검증 자료는 `output/playwright/contextual-item-guide-v1/`에 있다. 테스트 fixture는 운영 계정·보상에 접근하지 않으며 실제 App, Board, 게임 엔진과 격리된 API 응답을 사용한다. 자동화한 브라우저 터치는 CDP의 실제 touchStart/move/end 이벤트이며 실물 iOS/Android 기기 검증이나 운영 배포를 의미하지 않는다.

검증 결과: 빌드 통과, 10개 테스트 파일의 72건 통과, 실제 브라우저 33개 검수 항목 통과. 다섯 아이템 모두 터치 드래그 생성과 터치 사용, 생성 후 재접속, 일반 2레벨 연결, 320/430px 및 한국어·영어·일본어 안내를 검수했다. 런타임 pageerror는 0건이다.
