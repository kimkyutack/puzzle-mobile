# 무지개등 조합 연출 v31

클라이언트 연출만 수정했다. 서버의 색 선택·타일 변환·피해 판정·리플레이·보상 규칙과 엔진 버전은 변경하지 않았다.

## 조합 단계

- 무지개등의 첫 effectId에 속한 타일만 빛으로 연결한다. 후속 폭발의 피해 범위를 변환 대상으로 잘못 강조하지 않는다.
- 가로/세로 줄바람·꽃폭탄·풀바람 조합은 선택된 같은 색 타일이 해당 아이템으로 변하는 모습을 실제 스프라이트로 표시한다. 원래 타일은 변환 시점에 부드럽게 사라진다.
- 합치기 520ms, 무지개등 충전 720ms, 빛 전달 500ms, 전체 변환 후 대기 180ms를 거친다. 모든 변환 아이템의 준비 시작 시각을 공유하고 각 아이템의 발사·폭발·비행이 이어진다.
- 무지개등 두 개는 합친 뒤 보드 전체로 퍼지는 두 겹의 파동을 표시한다.
- 무지개등 확대를 약 1.8배로 조정하고 흔들림·궤도 장식·다중 테두리를 줄였다. 가는 금빛 연결, 이동하는 빛 알갱이와 약한 중심 광원을 사용한다.

## 표시 누락 방지

특수 이벤트 12개 이후를 생략하던 제한을 제거했다. 예약된 효과마다 GPU 스프라이트를 선점하지 않고 시작 시점에 최대 180개의 풀에서 배정·재활용한다. 실제 변환 아이템·비행체·주요 폭발이 장식 효과보다 우선한다. 대량 조합의 개별 폭발과 줄바람에는 간결한 연출을 적용해 화면을 가리는 파편과 섬광 중첩을 줄였다.

## 검증과 범위

- 관련 11개 테스트 파일·73개 테스트, TypeScript 검사와 별도 출력 경로의 Vite 빌드 통과.
- 네 가지 상대 아이템의 양방향 교환, 12개 초과 타일 변환·발동, 전체 변환 후 발사, 변환 칸으로 나중에 떨어진 타일의 수명, 기존 리플레이 상태 불변·효과 종료를 확인했다.
- 브라우저에서 390px 폭탄 변환, 풀바람 재생 종료 후 입력 활성화, 320px 모서리 단독 무지개등을 확인했다. 마지막 보조 광원 수정 후 재촬영은 브라우저 연결 시간초과로 완료하지 못했다.
- 검증 화면은 `tools/rainbow-v31-fixture.html`이며 실제 API를 호출하지 않는다. `partner=wind-row|wind-column|bomb|glider|rainbow`, `single=1`, `corner=1`, 검증용 프레임 정지 `stop=<ms>`를 지원한다. 사용자 설정 항목은 추가하지 않았다.
- 이 대화에서는 Git 상태·운영 배포·네이티브 리소스를 변경하지 않았다. 네이티브 앱에는 다음 웹 리소스 동기화·재빌드 시 반영된다.
