# AdMob 실제 광고 연결

2026-11-10 앞쪽 Chrome 창의 `hiddenstagedev@gmail.com` 계정에서 두 단위를 확인했다. 다른 Chrome 창의 게시자 계정은 이 프로젝트와 무관하다.

| 플랫폼 | 앱 ID | 하트·코인 2배 공용 보상형 단위 |
| --- | --- | --- |
| Android | `ca-app-pub-8278526737142254~8377793165` | `ca-app-pub-8278526737142254/9847446642` |
| iOS | `ca-app-pub-8278526737142254~9512404728` | `ca-app-pub-8278526737142254/4199921188` |

광고 위치는 레벨 5부터 하트 메뉴의 **광고 보고 하트 +1**, 일반전 최초 클리어 결과의 **광고 보고 보상 2배**다. 코인 2배는 기본 코인만 추가하며 별·이벤트 보상은 늘리지 않는다.

광고 일일 한도는 하트 5회, 코인 2배 10회이며 **한국 시간 매일 00:00**에 갱신한다. 광고 승인 시각으로 한국 날짜 구간을 집계하므로 기존 UTC 날짜 키가 있는 기록도 올바르게 포함한다. 늦게 도착한 보상 콜백은 처음 승인한 한국 날짜에 귀속한다. 이 변경은 서버에서 적용되며 별도의 앱 재빌드가 필요하지 않다.

하트 광고 버튼에는 `오늘 4/5회 남음`처럼 서버의 남은 횟수를 표시한다. 시청/취소/보상 확인과 화면 복귀 및 자정에 갱신하고, 0회이면 버튼을 비활성화한다. 같은 플랫폼 단위에서 재사용 가능한 취소·광고 없음 요청은 횟수를 돌려준다. 운영 API 버전 `7ae53c3b-91bb-4063-89f2-b9c0004702e5`에 조회 응답을 추가했으며, iOS·Android 리소스 동기화까지 완료했다. 이 버튼 표시는 새 앱 빌드에 포함되어야 한다. 타입 검사와 테스트 79개, 합성 API/SDK를 사용하는 실제 하트 화면의 브라우저 검수 9개가 통과했다.

앱 ID는 네이티브 프로젝트에 반영했다. 서버는 기존 플랫폼 헤더로 단위를 선택한다. 광고를 닫거나 표시 Promise가 완료되는 것만으로 보상 이벤트를 만들지 않는다. SDK Rewarded 이벤트는 확인 중 상태만 만들고, 실제 지급은 Google ECDSA 서명·사용자·광고 단위·원래 예약 시간대를 확인한 SSV 콜백으로 처리한다. 콜백 중복 도착에도 한 번만 지급한다.

두 단위의 광고 형식은 **보상형**, 보상은 **1 Reward**다. 2026-11-11 URL 확인 화면에서 HTTP 400이 보고되었다. 기존 서버는 콘솔 확인 요청에도 실제 사용자·예약 ID를 요구했고, 운영에는 플랫폼별 단위 허용 목록도 아직 반영되지 않았다.

확인 요청의 광고 단위 불일치를 별도로 처리하는 서버 버전 `7e673418-94c5-4add-a48c-a8caadb84020`에서 사용자 재시도로 **AdMob 화면 확인 성공**과 **Google 서명 검증 후 HTTP 200**을 모두 확인했다. 실제 확인용 단위는 `1234567890`이었고, 처리 중 DB 조회는 0회였다. 이후 사용자가 Android·iOS 두 URL 모두 저장 완료했다고 확인했다.

2026-11-11 실제 광고 활성화 버전 `73c874fd-a648-408b-82b3-65bdff73276d`를 운영에 100% 배포했다. `config/admob.json.enabled=true`, `testMode=false`이며 플랫폼별 실제 단위와 운영 콘솔의 광고 기능 활성 상태를 확인했다. `npm run native:release`로 웹 리소스를 빌드하고 iOS·Android 프로젝트에 동기화했다. 두 프로젝트의 메타데이터와 진입 JS 해시가 일치하고, 실제 앱 ID 및 테스트 모드 꺼짐 설정이 반영됐다. 타입 검사·관련 테스트 66개·로컬 workerd 검증 8개가 통과했다. 아카이브/스토어 업로드는 실행하지 않았다. 실제 광고 재생과 보상 지급은 새 네이티브 빌드 설치 후 기기에서 확인해야 한다.

콘솔 확인에서는 **사용자 ID와 맞춤 데이터 두 칸 모두 `admob-ssv-check`**를 입력한다. 2026-11-11 재시도 로그에서 Google 서명·확인 표식·보상 수량/종류는 통과했지만 실제 단위와 다른 확인용 광고 단위가 전송되어 `INVALID_SSV_PLACEMENT`로 거부된 것을 확인했다. 진단 로그에는 사용자 ID·예약 ID·서명·원본 URL을 남기지 않는다.

서버는 Google 서명·보상 수량과 종류를 먼저 검사하고 두 확인 표식이 정확히 일치할 때만 확인용 단위 번호를 허용하여 `verificationOnly:true`로 응답한다. 이 요청은 보상 DB를 조회/수정하거나 보상 지급 작업을 만들지 않고, 저장 함수에서도 확인용 요청을 별도로 거부한다. 서명 없는 요청, 변조된 요청, 확인 표식이 한쪽만 일치하는 확인용 단위 요청은 성공 처리하지 않는다. 실제 광고 콜백은 기존 단위 허용 목록·사용자·예약·시간대·중복 검증을 그대로 거친다.

완료 순서:

1. AdMob → 해당 앱 → 광고 단위 → 보상형 단위 → 고급 설정 → 서버 측 확인에 `https://puzzle-mobile.ddr1323.workers.dev/api/ads/ssv`를 입력한다. 사용자 ID와 맞춤 데이터 두 칸 모두 `admob-ssv-check`를 입력하고 **URL 확인 → 확인된 URL 사용 → 저장**한다. 두 플랫폼 모두 적용한다. 보상은 `1 Reward`를 유지한다. 실제 AdMob 콘솔 확인 성공은 사용자가 수행한 결과를 확인해야 한다.
2. `config/admob.json`의 `enabled`를 `true`, `testMode`를 `false`로 두고 `npm run admob:configure && npm run api:types`를 실행한다.
3. 검증 후 기존 운영 배포 경로로 서버를 배포한다. 기존 예약의 단위·보상 허용 목록은 지우지 않는다.
4. `npm run native:release`로 웹 리소스와 네이티브 프로젝트를 동기화한다. 이후 Xcode 아카이브/Android 빌드가 필요하다.
5. 테스트 기기 등록을 사용해 양 플랫폼의 로드·완주·중도 닫기·서명 콜백 도착·한 번만 지급됨을 확인한다. 개발 확인을 위해 실제 수익 광고를 클릭하지 않는다. 로컬 `native:ads-test`의 Google 데모 광고는 운영 단위 SSV 검증을 대신하지 않는다.

서버는 공개 콜백이라도 임의 호출이나 서명 없는 테스트 요청을 승인하지 않는다. AdMob URL 테스트 때문에 검증을 우회하지 않는다.
