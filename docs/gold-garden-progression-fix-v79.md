# 황금정원 완료 후 스테이지 복귀 v79

사용자 제보: 543레벨에서 황금정원을 여러 번 완료해야 일반 스테이지 버튼이 돌아오며, 일부 판에서는 골드가 늦게 표시되거나 추가 지급이 없었다.

## 원인과 변경

`goldGardenStatus`는 현재 진행 구간과 관계없이 과거의 미수령 보너스를 모두 반환했고, 홈은 그 목록의 첫 항목으로 일반 레벨 버튼을 교체했다. 현재 판을 완료해도 오래된 보너스가 다음 버튼을 계속 대체하므로 재실행해도 반복됐다. 실제 사용자 계정의 거래 내역을 조회한 것은 아니며, 동일한 진행 상태와 누적 이력으로 로컬에서 재현했다.

- 서버 대기 목록을 현재 레벨이 속한 100레벨 구간의 완료 보너스로 제한한다. 예: 다음 레벨 544이면 500레벨 보너스만 대상으로 삼고, 수령 후에는 빈 목록을 반환한다. 기존 앱도 이 응답을 사용한다.
- 클라이언트에서도 같은 조건으로 선택해 이전 Worker가 과거 목록을 반환해도 일반 스테이지 복귀를 막지 않는다.
- 홈과 승리 화면이 함께 마운트되어 있으면 계정별 수령 완료 이벤트로 둘 다 갱신한다. 수령 전에 시작된 조회가 늦게 도착해도 완료된 항목을 되살리지 않는다.
- 기존 클리어 기록, 보상 수령 기록 및 코인 원장을 삭제하거나 임의 지급하지 않는다. 서버 재생 검증과 보너스별 1회 지급 규칙을 유지한다. DB 마이그레이션은 필요 없다.

## 확인

- 관련 3파일 39테스트 통과. 과거 보너스가 누적된 레벨 544, 구간 경계, 명시적 스테이지 선택, 이후 600레벨 보너스, 재시도 중복 차감/지급 방지 등을 포함한다.
- `npm run build` 통과. 기존 큰 번들 경고만 있다.
- 실제 `GoldGardenEntry`·`CascadeBoard`와 실제 API 함수·마이그레이션을 적용한 독립 SQLite 서버를 연결해 브라우저에서 확인했다. 운영 API는 사용하지 않았다. 첫 19이동은 정상 엔진 재생 로그로 복원하고 마지막 이동을 실제 보드 입력으로 진행했다.
- 누적 이력: 100·200·300·400·500레벨 보너스가 미수령인 레벨 544. 500레벨 황금정원 완료 후 코인 500→693, 수령 기록 1개와 원장 +193 한 건. 홈·승리 버튼 갱신, 늦게 도착한 이전 응답 무시, 재실행 후 레벨 544 및 다음 버튼 동작 확인.
- 응답 유실: 100레벨 보너스 지급 직후 응답을 버리고 재시도. 코인 500→658, 원장 +158 한 건과 수령 기록 한 개를 유지하며 재실행 후 레벨 101로 진행한다.
- 최종 브라우저 `pageErrors: []`. 검증 화면의 개발용 자동 갱신 간섭을 제거하기 위해 별도 HMR 비활성 서버에서 최종 확인했다.

근거: `output/verification/gold-garden-recovery-v79/{verification.json,browser-final.log,browser-client-only.log,tests.log,build.log}`. 재현용 서버·화면·브라우저 코드도 같은 디렉터리에 있다.

현재 소스 수정과 로컬 검증을 완료했다. 운영 배포, 네이티브 동기화 및 실제 계정의 과거 보상 내역 대조는 수행하지 않았다.
