# 전체 메뉴 알림 점검 v46

홈, 푸터, 이벤트 탭, 메뉴 내부 버튼의 빨간점을 같은 수령·플레이 상태로 계산하도록 수정했다. 새 이미지나 레이아웃 변경은 없다.

## 표시 기준

| 항목 | 빨간점 표시 조건 | 표시하지 않는 상태 |
| --- | --- | --- |
| 출석 선물 | 현재 출석 보상 수령 가능 | 수령 완료, 운영 중지, 조회된 기간 종료 |
| 시즌 이벤트 | 진행 중인 시즌의 달성한 미수령 개인/가입 길드 보상 | 목표 미달, 수령 완료, 시즌 종료, 미가입 길드 목표 |
| 정원 패스 | 열린 무료 보상, 보유한 프리미엄의 열린 보상, 가입 길드에 전달 가능한 미사용 선물권 | 미달성 단계, 미보유 프리미엄, 수령/전달 완료 |
| 일일·주간 미션 | 현재 기간에 달성한 미수령 미션 | 미달성, 수령 완료, 기간 종료, 운영 중지 |
| 보물 카드 | 남은 도전 또는 진행 중인 마지막 도전 | 모든 도전 종료, 이전 날짜의 만료된 판 |
| 꽃빛축제 | 참여 가능, 진행 중인 복원, 이미 얻은 복원 보상 | 해금 전, 완성, 보상 없는 만료 상태 |
| 동물 구출 원정 | 레벨 20 이후 완료하지 않은 코스/이어하기 | 해금 전, 5코스 완료 |
| 도구 축제 | 오늘 시작 가능, 진행 중인 도전, 달성한 미수령 보상 | 오늘 완료, 보상 없는 만료 상태, 운영 중지 |
| 시작 아이템 무제한 | 설정된 실제 10분 진행 시간 | 진행 시간 밖, 이벤트 비활성 |
| 선물함 | 받을 아이템 또는 하트 용량이 남은 상태의 하트 선물 | 빈 선물함, 가득 찬 하트만 보관 중 |
| 운영 보상 | 게시·진행 중이고 실제 보상이 있는 미수령 이벤트 | 예약, 종료, 일시 중지, 수령 완료, 보상 없음 |
| 친구 | 처리 가능한 받은 친구 요청 | 보낸 요청, 차단 관계, 삭제된 정원사, 처리 완료 |
| 길드 | 관리 권한이 있고 정원이 남은 길드의 대기 신청 | 일반 멤버, 인원 가득, 미가입, 처리 완료 |
| 공지·고객센터 | 실제 읽지 않은 공지/답변 | 읽음 처리, 공지 게시 기간 종료 |

상점·유료 패키지는 구매 가능하다는 이유만으로 빨간점을 표시하지 않는다. 이야기는 실제 이야기 상태를 불러오기 전에는 새 이야기 표시를 만들지 않는다.

## 수정한 원인

- 전체 이벤트 알림 합계, 첫 원정 여부, 첫 미니게임 도전 여부 등 서로 다른 기준을 홈/푸터에서 사용하던 부분을 정리했다.
- `packages/content/src/attention.ts`의 수령·플레이 규칙을 서버와 클라이언트에서 공유한다. 이벤트 아이콘, 홈 바로가기와 푸터는 같은 규칙과 운영 기능 설정을 사용한다.
- `/progression`은 이미 조회한 이벤트 보상과 선물 종류별 개수를 응답에 포함한다. 추가 DB 왕복은 없다. 구 서버 응답에는 클라이언트가 기존 `/events` API로 보완하는 호환 경로가 있다.
- 미션, 패스, 출석, 선물 수령과 친구/길드 처리 후 최신 상태를 공유한다. 진행 중인 조회가 있으면 재조회 요청을 합쳐 처리하고, 보상 수령 전의 늦은 응답이 최신 화면을 덮지 않도록 했다.
- 이벤트 종료 시간, 일일·주간 기간과 운영 기능 중지를 반영한다. 공지 읽음과 운영 보상 수령도 각각 별도로 갱신한다.
- 친구 목록에서 숨기는 차단 관계를 서버 알림 집계에서도 제외했다. 길드 정원과 관리 권한도 확인한다.

## 검증

- 8개 테스트 파일 / 77개 테스트 통과. 실제 마이그레이션과 SQL을 사용하는 서버 함수 테스트에 남은 미니게임 도전, 원정 중간 코스, 만료 이벤트, 보상 수령, 선물 종류, 차단된 친구 요청, 길드 권한·정원을 포함했다.
- 클라이언트 TypeScript 검사 및 전체 웹 빌드 통과. 운영 설정을 사용하는 Worker 패키징 dry-run 통과. 업로드하지 않았다.
- 실제 `App`을 사용하는 390×844px 격리 브라우저에서 홈/이벤트 완료 상태의 빨간점 0개, 남은 플레이 표시, 미션→패스→선물→출석→시즌 순서로 수령 후 해당 메뉴 및 푸터의 점 제거를 확인했다.
- 가득 찬 하트 선물, 친구 수락, 길드 가입 승인, 공지 읽음, 운영 보상 수령, 운영 중지 기능도 확인했다.
- 수령 전 조회를 1.5초 지연시킨 뒤 선물을 받아도 늦은 응답으로 점이 되살아나지 않았다. 구 서버의 보상 상태 응답 호환 경로도 확인했다.
- 브라우저 데이터는 합성 상태다. 운영 계정/실물 Android·iOS 검증은 하지 않았다. 서버 배포, 네이티브 동기화, 커밋/푸시는 하지 않았다.
