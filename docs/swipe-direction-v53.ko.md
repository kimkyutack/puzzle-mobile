# 타일 스와이프 방향 입력 수정

## 재현된 문제

보드가 첫 4px 정도의 이동에서 가로/세로 축을 고정했다. 첫 터치가 아래로 5px, 오른쪽으로 1px 흔들린 후 왼쪽으로 30px, 아래로 14px 움직이면, 왼쪽 스와이프가 아래쪽 교환으로 처리됐다. 9열 보드 중앙 40번에서 의도한 목적지는 39번인데 수정 전 실제 Action은 `40 → 49`였다. 동일한 보드 컴포넌트에 동일한 합성 touch PointerEvent 경로를 전달한 브라우저 비교에서 수정 후 `40 → 39`로 바뀌었다.

이 재현은 사용자 신고와 같은 종류의 방향 오류를 확인한 것이며, 해당 사용자의 iPhone에서 발생한 모든 사례의 원인이 이것 하나라고 확정한 것은 아니다.

## 변경

- 작은 이동은 손가락을 따라 미리보기만 한다. 한 칸의 28% 이상 움직이고 주축 이동이 보조축의 1.25배 이상일 때 축을 고정한다. 고정 후 손떨림으로 축을 바꾸지 않으며 의도적인 같은 축 방향 반전은 유지한다.
- 손을 떼기 직전에 방향을 바꿔도 이전 이웃 타일 미리보기를 복구한 후 최종 목적지를 표시한다. 원점으로 돌아온 드래그는 아이템 탭으로 처리하지 않는다.
- 이동 모션이 남아 있으면 다음 입력을 받지 않는다. 느린 프레임에서 교환 완료 타이머가 마지막 렌더 프레임보다 먼저 실행돼도 두 타일을 교환 목적지에 확정한 뒤 특수 효과에 넘긴다.
- 일반전과 동물 구출 원정이 공유하는 Board에 적용했다. 엔진 판정, 아이템 생성 규칙, 서버 재생 결과는 변경하지 않았다.

## 검증

- 타입 검사 통과. 관련 7개 테스트 파일 47개 테스트 통과.
- 프로덕션 웹 번들 생성 통과. 기존 대형 chunk 경고는 남아 있다. 기존 dist를 덮지 않도록 `/private/tmp/puzzle-swipe-v53-build`에 생성했다.
- 실제 Board/CascadeBoard를 사용하는 390 × 844 격리 브라우저 검증: 특수 아이템 6종 × 네 방향의 합성 터치 경로 24개와 브라우저 포인터 드래그 네 방향이 모두 기대한 Action을 생성했다.
- 4개 매치로 39번에 세로 로켓이 실제 생성되는 연출을 끝낸 직후 그 로켓을 왼쪽 38번으로 드래그: turn 2로 정상 진행하고 연출 후 잠금 해제.
- 무지개+폭탄 조합 네 방향, 손을 떼며 반전, 원점 복귀 취소, 모션 축소, 연출 중 즉시 연속 입력 검사. 연속 입력은 첫 교환 1회만 처리했다.
- 보드 초기화 전에 검사 버튼을 누른 경우와 긴 조합 연출 대기에서 검수 도구의 타임아웃이 있었다. 캔버스 초기화 및 실제 종료 상태를 확인한 뒤 다시 검사했다. 이는 실기기 검사 완료를 의미하지 않는다.

증거: `output/verification/swipe-direction-v53/browser-checks.json`, 수정 전후 화면, 수정 전 Board 스냅샷. 재현 도구는 `tools/swipe-v53-fixture.html`과 `tools/swipe-v53-harness.tsx`다. 운영 API 요청, 배포, 네이티브 동기화, iOS/Android 빌드 및 실기기 검사는 하지 않았다. 설치된 앱 반영에는 수정된 웹 리소스를 포함한 새 네이티브 빌드가 필요하다.
