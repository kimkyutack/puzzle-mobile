# 꿀벌집 생성과 조합

꿀벌집은 상점 재고가 아닌 보드에서 생성되는 특수 타일이다. 직접 수행한 한 번의 일반 타일 교환에서, 교환한 두 타일이 서로 다른 색의 정확히 3개 매칭을 각각 완성하면 이동한 타일의 도착 칸에 하나 생성한다. 두 색의 수집 목표는 생성 칸을 포함해 모두 계산한다. 연쇄 낙하, 특수 타일 교환, 4개·5개·정사각형 등 기존 생성 패턴에는 이 조건을 적용하지 않는다.

## 사용

탭하거나 이웃 타일과 교환하면 이동 1회를 사용해 벌 3마리를 보낸다. 벌은 남은 목표 장애물을 우선하고, 같은 우선순위에서는 내구도가 큰 장애물을 선택한다. 한 번 선택한 장애물을 계속 타격하며, 먼저 깨지면 남은 벌이 다음 목표를 고른다. 물관은 동일한 장애물 ID를 따라 이동한 앵커를 공격한다. 공격 가능한 장애물이 없으면 서리·수집 타일 등 기존 목표 선택으로 돌아간다. 색상 화분, 꽃봉오리, 차양, 색 조건이 있는 저장함의 조건은 건너뛰지 않는다. 씨앗을 직접 공격하지 않는다.

## 조합

| 상대 | 효과 |
|---|---|
| 가로/세로 로켓 | 벌 3마리가 해당 방향 로켓을 운반한다. 도착지에서 로켓을 발동한다. |
| 꽃폭탄 | 벌 3마리가 폭탄을 운반한다. 도착지에서 폭탄을 발동한다. |
| 씨앗비행기 | 벌 5마리가 집중 타격한다. |
| 꿀벌집 | 벌 6마리가 집중 타격한다. |
| 무지개등 | 가장 많은 색의 일반 타일이 꿀벌집으로 바뀌고 각각 벌 3마리를 보낸다. |

운반 공격은 다음 벌의 목표를 고르기 전에 실제 피해를 처리한다. 이미 깨진 장애물에 남은 운반 공격을 낭비하지 않으며, 조합은 어느 방향으로 교환해도 동일하다.

## 규칙 및 연출

새 규칙은 `BEEHIVE_ENGINE_VERSION` 1.5.0부터 지원한다. 1.4.0 이하의 진행 중인 판에는 생성 규칙을 소급 적용하지 않는다. 기존 규칙으로 저장된 판의 재생 결과를 유지한다. 앱과 Worker가 공통 지원 규칙을 선택하므로 소스 수정만으로 설치된 앱에 기능이 추가되지는 않는다.

전용 투명 PNG `beehive`, `bee_flight`를 사용한다. 벌집 준비 620ms, 벌 비행 720ms, 출발 간격 260ms이며, 개별 도착에 맞춰 장애물 숫자와 이미지가 바뀐다. 운반한 로켓·폭탄은 벌이 도착한 뒤 준비 및 발동 연출을 시작한다. 연출은 로컬이며 게임 상태와 재생 해시는 변경하지 않는다. 벌 비행 이벤트 자체는 추가 아이템 사용 횟수로 중복 집계하지 않는다.

이미지 원본은 `packages/assets/source/`, 생성 이력은 `packages/assets/beehive-prompts.json`에 있다. `tools/asset-pipeline/beehive.ts`는 다른 에셋이나 네이티브 프로젝트를 다시 만들지 않고 새 이미지 두 개만 등록하는 작업이다. 전체 에셋 파이프라인에서도 두 이미지의 원본과 생성 이력을 유지한다.

## 검증 범위

`tests/beehive.test.ts`는 실제로 가능한 초기 배치의 양방향·세로 동시 매칭, 기존 규칙 보존, 집중 타격·재지정·물관·색상 조건, 모든 조합의 양방향, 결정적 재실행, 미션·도움말·타격 시간을 검사한다. `tests/client-beehive-effects.test.ts`는 실제 이벤트의 벌집·벌·운반물 연출, 유한 좌표, 180개 이내 풀 제한 및 종료 후 정리를 검사한다.

이 작업에서는 앱 빌드, 네이티브 동기화, 배포, 푸시를 수행하지 않는다.

관련 검사 7개 파일 62개 테스트와 타입 검사를 통과했다. 실제 보드에서 생성, 기본 사용, 여섯 조합의 연출 종료 및 입력 복귀를 확인했다. 새 이미지 두 개의 크기·알파·SHA-256 및 두 매니페스트 일치도 확인했다. 증거는 `output/verification/beehive-v32/`에 있다.

전체 검사 당시 417개 중 416개가 통과했고, 기존 `client-visual-timing.test.ts`의 연출 시간 제한 검사 1건이 실패했다. 꿀벌집 전용 시간 계산을 제거한 비교본과 유지 규칙 1.3.0의 행동 2,257개를 비교했을 때 연출 시간 차이는 0건이었다. 이 실패는 이번 기능을 위해 제한을 완화하거나 다른 연출을 변경해서 숨기지 않았다. 다른 작업이 같은 체크아웃을 수정 중이므로 이 기록은 검사 당시 소스 범위의 결과다.
