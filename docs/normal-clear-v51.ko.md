## 씨앗 저장함과 목표

기존 74·86·98레벨은 씨앗 저장함이 씨앗 출구와 겹쳤다. 저장함이 열릴 때 씨앗이 생성되고 같은 중력 처리 안에서 바로 수집되므로 별도 운반 과정이 없었다.

새 맵은 저장함을 출구보다 세 행 위로 옮기고, 아래쪽에 독립적으로 파괴하는 상자를 두어 씨앗이 보드에 머문 뒤 출구로 내려가도록 구성했다. 저장함에는 기존 씨앗 보따리 이미지로 내용물을 표시한다. 씨앗 출구에는 금색 아래 화살표와 접근성 라벨을 추가했다. 게임 규칙·씨앗 수집 조건은 변경하지 않았다.

## 70~100레벨 전체 검토

31개 레벨을 검토하고 15개 도전 맵을 새로 검증했다: 72, 73, 74, 76, 77, 78, 82, 84, 86, 87, 92, 94, 96, 97, 98.

일반전의 색 수집량, 화분 내구도, 어려움 단계의 서리 층, 씨앗 운반 경로를 조정했다. 78레벨은 초기에 제공되던 로켓·폭탄 대신 직접 특수 타일을 만들고 조합하게 했다. 쉬는 판, 정원 스토리 판과 기존에 충분한 공략이 필요했던 맵은 유지한다. 새 맵은 일반 단계 24~26회, 어려움 28~30회, 매우 어려움 30~35회의 이동 횟수를 제공한다.

검증 배치 기준으로 86레벨의 도구 없는 완료 경로가 4회에서 15회, 72레벨이 6회에서 16회, 78레벨이 4회에서 28회로 바뀌었다. 이는 자동 공략 결과이며 최단 경로나 실제 사용자 승률을 뜻하지 않는다.

`midgameBalancedLevel`은 현재 공통 엔진의 신규 판에만 인증된 맵 데이터를 제공한다. 기존 `Run.level`과 구형 엔진의 보관된 맵·행동 기록은 변경하지 않는다. 시작 시 일반 타일 랜덤 배치도 유지한다. 다시 만들기는 `node --import tsx tools/level-validation/midgame-v51.ts`, 정적 완료 기록 검증은 같은 명령의 `--verify` 옵션을 사용한다.

## 클리어 후 대기

- 승리 연출과 보상 미리보기는 로컬에서 계속 즉시 표시한다.
- ‘다음 레벨’ 버튼은 보상 확정 응답에 묶지 않는다. 다음 목표·시작 도구 화면을 먼저 열며, 로컬 승리 시 다음 맵 다운로드를 미리 시작한다.
- `/levels/next`는 선택적 `levelId`로 현재 레벨 또는 바로 다음 레벨까지만 조회한다. 이 조회는 진행도·재화를 변경하지 않는다. 플레이어의 실제 레벨은 계속 서버 응답으로만 갱신한다.
- 승리 행동 배치는 선택적 `finishOnWin: true`를 함께 보낸다. 서버가 행동을 재실행해 승리를 확인한 경우, 행동 저장과 코인·별·꽃빛축제 꽃잎·미션·패스·10판 보상 확정을 하나의 기존 D1 원자적 배치에서 처리한다. 클라이언트가 주장한 결과·보상은 사용하지 않는다.
- 새 서버의 정상 경로는 `/actions` 다음의 별도 `/finish` 왕복이 사라진다. 구형 서버가 옵션을 무시하면 기존 `/finish`로 이어지는 호환 경로를 유지한다.
- 전송 중 배치는 옵션을 포함해 그대로 영속화하므로 응답 유실·재접속 후에도 동일한 키와 입력으로 재시도한다. 중복 요청·동시 요청은 보상을 중복 지급하지 않는다.
- 실제 다음 판 생성·시작 도구 사용은 이전 판 저장이 확인된 뒤에만 진행한다. 네트워크가 끊긴 상태에서 새 판을 임의로 시작하거나 미확정 재화를 사용하지 않는다.

## 검증 기록

`output/verification/normal-v51/`에 격리된 실제 App·Board 브라우저 검사, 자동 공략, 랜덤 배치 표본 및 테스트 결과를 저장한다. 브라우저 검사는 실제 API 호출을 모두 메모리 응답으로 교체하므로 운영 계정이나 보상을 변경하지 않는다. 서버 테스트는 실제 마이그레이션과 SQLite 트랜잭션을 사용해 중복·경쟁·롤백을 확인한다. 운영 Cloudflare 왕복 시간 자체를 측정한 결과는 아니다.

최종 확인: 관련 테스트 16개 파일·115개 통과, 타입 검사 통과. 인증 맵 15개의 완료 기록을 다시 재생해 검증했다. 추가 랜덤 시작 45개는 모두 유효한 초기판을 생성했고, 탐욕적 자동 공략은 38개에서 성공했다. 이는 플레이어 승률이나 나머지 7개 맵의 불가능성을 의미하지 않는다. 390×844 및 320×658에서 목표 영역과 씨앗 출구를 확인했고, 320px에서 가로 넘침이 없었다. 실제 App에서 응답 보류·실패·재시도 및 기존 `/finish` 호환 흐름을 검증했다. 새 서버 경로에서 별도 `/finish` 호출 없이 다음 판이 시작되며 코인은 한 번만 50 지급됐다.

브라우저 실행 오류는 없었다. 여러 검사 화면을 전환하는 동안 Pixi의 바인딩된 텍스처 해제 경고가 기록됐다. 이 작업에서는 렌더러의 텍스처 수명 관리까지 변경하지 않았으며, 경고 원문을 `browser-proof.json`에 보관했다.
