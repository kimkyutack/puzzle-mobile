# 강아지 구출 원정과 게임 이벤트 운영

## 플레이 규칙

- 원정은 10단계다. 각 단계의 재도전 배치는 3개씩이며 총 30개 배치의 도구 없는 클리어 기록을 검증했다.
- 원정의 목표 아이콘·보드 동물·안내 포스터·최종 보상은 꼬마 웰시코기다. 일반전의 토끼 길 안내 스테이지는 그대로 유지한다.
- 하단에는 재시도와 나가기 두 버튼만 표시한다. 재시도 확인창에서 현재 판을 초기화하고 도전 횟수 1회를 사용하는 것을 안내한다.
- 기본 도전 횟수는 하루 3회다. 새 단계 시작 및 재시도마다 1회 사용하고, 보관된 판 이어하기에는 횟수를 쓰지 않는다. 남은 횟수가 0이어도 저장된 판과 미수령 클리어 보상은 이어서 확인할 수 있다.
- 한국 시간 00:00이 기준이다. 서버 시각의 KST 날짜와 `dailyAttempts.day`를 비교하므로 별도 크론이 필요하지 않다. 날짜가 바뀌어도 저장된 판은 초기화하지 않는다.
- 하트와 보유 아이템은 소모하지 않는다. 10단계를 마치면 코인 300, 별빛 대폭탄 2개와 꼬마 웰시코기 1마리를 받는다.

## 기존 진행과 중복 처리

- 예전 5단계를 완료한 계정은 6단계부터 진행한다. 진행 중인 이전 버전의 판도 해당 판 정의 그대로 검증한다.
- 기존 토끼 보상이나 배치한 정원 동물은 회수하지 않는다. 강아지는 별도 안정적인 지급 ID `woodland-dog-v2`로 10단계 완료 시 한 번 지급한다.
- 횟수와 새 판은 기존 플레이어 버전 비교 및 D1 트랜잭션과 함께 저장한다. 같은 요청 재전송은 추가 차감하지 않는다. 두 기기에서 같은 판을 동시에 재시도하면 한 요청만 적용되고 다른 요청은 변경된 판 안내를 받는다.
- 횟수 소진/다른 기기 변경 오류가 발생하면 앱은 플레이어 상태를 다시 조회한다. 정상 플레이 중 타일 계산은 계속 로컬에서 처리한다.
- 횟수를 소진했고 이어갈 판도 없으면 원정 버튼의 빨간점을 제거한다. 다음 KST 날짜에는 새 도전 가능 상태로 돌아온다.

## 운영 콘솔

`/admin` → **이벤트 → 게임 이벤트 운영**에서 아래 항목을 설정한다.

| 이벤트 | 운영 항목 |
| --- | --- |
| 꽃빛축제 | 활성화, 개최 시작/종료, 해금 레벨, 신규 참여자의 개인 진행 일수 |
| 동물 구출 원정 | 활성화, 개최 시작/종료, 해금 레벨, 하루 도전 횟수 |
| 도구 축제 | 활성화, 개최 시작/종료, 해금 레벨 |
| 보물 카드 | 활성화, 개최 시작/종료, 해금 레벨 |
| 시작 아이템 무제한 | 기존 일정 화면에서 활성화와 매일 시작 시각 |

시각은 관리자 컴퓨터의 시간대와 관계없이 한국 시간으로 입력·변환한다. 빈 시작 시간은 즉시, 빈 종료 시간은 종료 미지정이다. 예약 종료는 신규 참여를 제한하고 이미 획득한 진행/보상 기록을 삭제하지 않는다. 기능 자체를 끄면 해당 이벤트의 요청과 노출을 중지한다.

원정 기본값은 해금 레벨 20·하루 3회·기간 미지정이다. 하루 횟수 설정은 1~20회이며 값을 변경해도 오늘 사용한 횟수는 유지한다. 개인 진행 일수 변경은 새 꽃빛축제 참가자에게만 적용한다. 이전 운영 설정에 새 필드가 없어도 기본값으로 읽는다.

검토창에서 일정·해금 레벨·횟수 등 실제 적용 값을 확인하고 작업 사유를 적어 저장한다. 기존 관리자 권한, CSRF, 설정 리비전 충돌 검사 및 운영 기록을 사용한다. 조회 전용 사용자는 수정할 수 없다. 같은 화면의 시간 이벤트와 게임 이벤트 설정은 저장 후 최신 리비전을 다시 읽는다.

## 검증

- 관련 10개 테스트 파일, 106개 테스트 통과. 날짜 경계, 횟수 소진·이어하기·중복 요청·동시 재시도, 기존 5단계 계정, 30개 배치, 강아지 지급 및 관리자 설정의 실제 Worker API 반영 포함.
- TypeScript·웹 빌드·관리자 빌드 및 Worker production 설정 드라이런 통과. DB 마이그레이션은 추가하지 않았다.
- 실제 UI 컴포넌트를 합성 API와 함께 브라우저에서 검사했다. 320×658, 390×844, 540×900 CSS px; 하단 버튼 각 56px, 이미지 누락과 새 콘솔 오류 없음. 영문 Retry/Leave 및 원정 레벨판 넘침 없음.
- 관리자 날짜 입력이 실제 저장되는 것과 KST 00:00이 전날 UTC 15:00으로 전송되는 것을 확인했다. 설정 저장 후 다른 일정 편집을 저장할 때도 최신 리비전과 앞선 변경을 유지한다. 조회 권한의 입력/저장 비활성화도 확인했다.
- 증거: `output/verification/expedition-v49/`의 `tests-final.log`, 빌드 로그, `worker-dry-run.log`, `browser-proof.json`, `admin-browser-proof.json`, 화면 캡처 및 `balance-report.json`.
- 안내 포스터는 내장 imagegen으로 수정한 프로젝트 자산이다. 경로와 프롬프트는 `packages/assets/expedition-v49/README.md`에 기록했다.
