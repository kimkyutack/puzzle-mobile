# 동물 구출 원정: 운영 회차와 전용 동물

운영 회차마다 한 종류의 동물을 구출합니다. 기본값은 회차 `001`, **아기 판다**이며, 다음 회차에서 운영자가 여우·레서판다를 선택합니다. 10단계 완주 보상은 해당 회차 동물 1마리입니다. 세 동물은 꾸미기 상점에 노출되지 않고 구매 API도 구매를 거절합니다.

## 운영 콘솔

`이벤트 → 게임 이벤트 운영 → 동물 구출 원정`에서 다음을 설정합니다.

1. 새 **원정 회차 ID** 입력: 예를 들어 `001` → `002` → `003`. 영문·숫자·하이픈·밑줄, 최대 64자입니다.
2. **구출 동물 · 완주 보상**에서 판다 → 여우 → 레서판다 선택.
3. 기존 시작·종료 시간, 해금 레벨, 하루 도전 횟수 설정.
4. **게임 이벤트 설정 검토**에서 동물·회차를 확인하고 작업 사유와 함께 저장.

동물과 회차 ID의 조합이 동일하면 기존 회차를 재개합니다. 새 회차를 원하면 새 ID를 사용합니다. 자동 순환이나 임의 날짜 초기화는 추가하지 않았습니다.

## 진행과 보상 보존

- 각 회차는 별도의 10단계 진행, 저장된 시도, 완료 기록을 가집니다.
- 새 회차가 열려도 이전 원정 메뉴를 선택해 저장된 판을 무료로 이어 할 수 있습니다. 저장된 맵과 보상 동물이 변경되지 않습니다.
- 새 단계·재시도 사용 횟수는 회차 전체에서 공유합니다. 기본 하루 3회, 한국 시간 00:00 초기화입니다. 회차를 바꿔도 추가 충전되지 않습니다.
- 서버는 저장된 시도 ID로 원정 회차를 찾고 실제 행동 기록을 재생한 후 보상을 확정합니다. 다른 회차가 활성화된 동안에도 이전 회차의 정당한 보상을 받을 수 있습니다.
- 재요청·동시 요청은 중복 보상을 지급하지 않습니다. 동물 보관함 지급과 플레이어 보상·진행은 기존 트랜잭션에서 함께 처리합니다.
- 기존 메타데이터 없는 원정은 `legacy-dog-v1` 강아지 회차로 유지합니다. 과거 토끼·강아지와 설치된 동물도 보존합니다.
- 새 정원 원화를 지원하지 않는 구버전 앱에는 응답에서만 강아지 원화를 대체 표시합니다. 서버에 저장된 전용 동물 종류·소유권·인스턴스 ID는 변경하지 않습니다. 새 앱은 `gardenArt=expedition-v50`으로 실제 동물을 받습니다.

## 원화와 검증

세 동물의 앞·뒷면/보행/하품/수면/기지개 원화 및 구출 포스터는 `packages/assets/expedition-v50`에 저장했습니다. 실제 정원 렌더러와 동일한 이동 시뮬레이션을 사용합니다. 기존 일반전 토끼 길 안내는 유지합니다.

검증 기록: `output/verification/expedition-v50`. 관련 테스트는 서버 SQLite 트랜잭션·보상/일일 제한·회차 보존·상점 구매 거절·운영 설정 저장·원화/네 방향 보행·알림/기존 기능 회귀를 포함합니다. 격리된 브라우저에서 320/390/540px 레이아웃, 판다 플레이, 여우 마지막 보상과 수령 후 빨간점 제거, 이전 판다 재개, 레서판다 영문 플레이, 실제 정원, 운영 회차 선택 저장을 확인했습니다.

이번 변경은 로컬 코드와 원화에 반영했습니다. 운영 서버 배포, 네이티브 동기화 및 앱 아카이브는 수행하지 않았습니다. 새 원화/UI는 앱 업데이트에 포함해야 합니다.
