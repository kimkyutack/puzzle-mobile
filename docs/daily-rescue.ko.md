# 하루 한 번 아이템을 받는 구름길 구조대

2026-11-05. 완료된 이야기 판을 다시 여는 기능을 일일 보상 미니게임으로 변경했습니다.

## 플레이 규칙

- 기존처럼 일반 퍼즐 7판 완료 후 `루미의 기록 → 구름길 구조대`에서 열립니다.
- 서버 기준 한국 시간 자정에 새로운 도전과 보상 수령 기회가 열립니다.
- 성공 시 시작 화면에서 안내한 기존 도구 1개를 계정 귀속 아이템으로 지급합니다. 일곱 종류가 일별로 순환합니다: 망치, 줄바람, 섞기, 꽃폭탄, 가로 쓸기, 세로 쓸기, 무지개통.
- 성공 보상은 계정당 하루 한 번입니다. 실패 시 하트나 보유 도구 소모 없이 재도전할 수 있습니다.
- 보상을 받은 날에는 `오늘 보상 수령 완료`로 표시하고 재도전 버튼을 제공하지 않습니다. 완료 화면에는 획득 아이템과 다음 도전 시각 안내가 나옵니다.
- 같은 날 중간에 나가면 진행을 이어갑니다. 다음 날은 새 판으로 시작합니다. 일반 레벨과 진행 중인 일반 퍼즐은 바꾸지 않습니다.

## 저장과 지급

`GET /api/story`의 선택 필드 `dailyRescue`가 서버의 날짜, 마감 시각, 아이템과 수령 여부를 전달합니다. 잠긴 계정에는 필드를 보내지 않습니다.

`POST /api/story/episodes/bridge-v1/complete`에 `{periodId, actions}`를 보냅니다. 서버는 인증, 해금, 현재 날짜, swap/tap만으로 구성된 합법 승리 기록을 검증합니다. 아이템 종류와 수량은 클라이언트 입력으로 받지 않습니다.

기존 경제 `mutate` 경로에서 플레이어 인벤토리, 귀속 아이템 lot, ledger, 일일 `reward_claims`와 이야기 완료 표시를 동일 D1 배치로 확정합니다. 날짜별 고정 operation key와 `reward_claims`의 기본키가 중복 지급을 막습니다. operation 영수증이 정리된 뒤에도 일일 claim은 유지됩니다. 추가 마이그레이션은 없습니다.

구형 클라이언트의 `{actions}` 요청은 과거 계약대로 이야기 완료 표시만 저장하고 일일 아이템은 지급하지 않습니다. 이미 구조 이야기를 완료한 계정도 새 일일 도전을 할 수 있습니다.

클라이언트 진행 키는 `garden-rescue-daily-v1-<account>-<server-period>`입니다. 과거 `garden-rescue-bridge-v1-<account>`의 완료 판은 불러오지 않습니다. 수령 요청 실패 시 이긴 행동 기록을 남겨 재시도할 수 있습니다. 수령 성공 후 해당 날짜의 진행 키만 지웁니다. 날짜 변경, 재접속, 다른 기기에서의 수령은 서버 상태를 다시 확인합니다.

## 검증

- `npx vitest run tests/daily-rescue.test.ts tests/flow-rescue.test.ts`: 10개 통과. 한국 자정 경계, 보상 주기, 계정/날짜/구형 캐시 격리, 미수령 승리 복구 및 기존 퍼즐 동작을 검사합니다.
- `npx tsx tools/api-daily-rescue-http.ts`: 실제 Worker를 격리 Miniflare와 임시 D1으로 실행합니다. 인증/해금, 위조/미완료/잘못된 날짜 거부, 구형 계약, 동시 수령/반복 요청, operation 정리 후 중복 방지, 이전 날짜 및 계정 격리를 확인합니다. 일반 레벨/하트/코인/별/진행 중 일반 판이 바뀌지 않는지도 검사합니다. 결과는 `output/verification/daily-rescue/http.json`입니다.
- `npm run typecheck` 통과. 별도 경로 `output/verification/daily-rescue/web`로 웹 빌드 통과(기존 대형 chunk 안내 있음).
- Chrome의 독립 로컬 검수 계정에서 시작 → 실제 타일 드래그 1회 → 나가기 → 이어하기(남은 이동 17회 복구) → 나머지 4회 이동 → 보상 받기 → 새로고침 → 기록장의 수령 완료 버튼 비활성화를 확인했습니다. 화면은 `output/verification/daily-rescue/claimed.png`와 `journal-claimed.png`입니다. 실제 iOS/Android 기기 검수는 포함하지 않습니다.

운영 배포와 iOS/Android 앱 재빌드/동기화는 이 변경에서 실행하지 않았습니다. 운영 적용 시 새 API와 새 클라이언트를 함께 반영해야 합니다. 기존 네이티브 산출물과 운영 계정/DB는 변경하지 않았습니다.
