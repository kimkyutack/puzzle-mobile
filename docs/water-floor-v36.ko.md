# 열린 물길의 같은 턴 재보충 수정

## 원인

1.7 규칙은 전체 연쇄와 보충을 마친 뒤 `advanceGardenStage`를 실행했습니다. 따라서 흙마개를 이미 타격한 뒤에도 그 턴의 중간 상태에서는 물길이 닫힌 것으로 취급되어, 새 타일이 채워지고 추가 매치가 발생했습니다. 최종 상태만 확인한 기존 테스트에서는 드러나지 않았습니다. 낙하 경로는 선언된 중력 경로를 따라 열린 칸을 통과할 수도 있었습니다.

## 변경

- 1.8 규칙은 각 타격 단계 직후, 중력과 보충 전에 물길/동물 길을 갱신합니다. 연결된 길의 기존 조각을 걷어내고 같은 턴의 첫 보충부터 열린 칸을 제외합니다.
- 실제 타일 레이어에만 열린 바닥의 투명 마스크를 적용합니다. 낙하가 빈 공간을 가로지르더라도 열린 물길 위에는 타일이 그려지지 않습니다. 바닥·물·토끼·숫자·장애물·이펙트는 기존 표시 순서를 유지합니다. 새로 열리는 칸의 마스크는 기존 타일 제거 시점에 바꿉니다.
- 기존 1.0~1.7 규칙은 유지하고 새 판은 협상된 1.8 규칙을 사용합니다. 기존 1.7 판의 최종 해시 24개를 그대로 확인했습니다. 설치된 구 앱이나 기존 진행 중인 판을 서버에서 강제로 새 규칙으로 바꾸지 않습니다.
- 24개 맵의 모양·목표·seed·이동 횟수는 그대로 유지했습니다. 새 처리 순서에 대한 무료 교환/탭 승리 로그를 `garden-stage-recipes-v3.json`, `garden-stage-proofs-v3.json`으로 분리했습니다.

## 검증 및 반영

- 자동 검사 68개 파일 / 468개 테스트 통과. 새 회귀 검사는 모든 중간 연쇄에서 연결된 칸이 비어 있는지, 개방 로그 뒤 해당 칸으로 fall/spawn이 발생하지 않는지, 기존 기록이 그대로인지 확인합니다. 320/390/556px 클립 픽셀 검사도 통과했습니다.
- 390×844의 실제 App 50레벨에서 첫 교환으로 물길 개방 → 다음 교환과 여러 차례 낙하 → 나머지 화단 개방과 승리까지 확인했습니다. 열린 가로/세로 물길이 계속 비어 있습니다. 일반 31레벨도 연쇄 후 입력이 해제됐습니다.
- 초기 시각 검수에서 새 타일 그룹에 맞지 않는 진단용 `getChildIndex` 참조 오류를 발견하고 수정했습니다. `browser-check.json`은 수정 전 오류와 수정 후 오류(0개)를 구분합니다. 배포 전 실제 앱을 다시 실행하고 촬영했습니다.
- TypeScript, Worker production dry-run, iOS Release API 검사 통과. iOS·Android 웹 리소스 533개 해시 일치. 기존 iOS 1.06(7) / Android 1.05(6) 버전 유지. Archive/스토어 업로드 없음.
- 운영 Worker `puzzle-mobile`에 배포 완료: `cbd0be17-fbef-499d-8836-9693d0a773d2`. 운영 `/api/health`에서 최신 1.8 및 이전 버전 지원을 확인했습니다. 운영 사용자 계정이나 실제 진행 중인 판을 수정하는 검사는 하지 않았습니다.

검증 자료는 `output/verification/water-v36/`에 있습니다. `open-floor-preview.mp4`는 실제 브라우저 녹화의 무음 미리보기이며, 프레임 인코딩 수치는 실물 기기 FPS 인증이 아닙니다. 실물 휴대폰 검수는 별도 범위입니다.

배포 CLI는 설치된 Wrangler 4.156.1의 help와 공식 [Workers 명령](https://developers.cloudflare.com/workers/wrangler/commands/workers/), [역할·권한](https://developers.cloudflare.com/workers/authorization/workers/)을 확인했습니다. 기존 운영 대상·바인딩을 유지하고 `--keep-vars --strict`로 배포했습니다.
