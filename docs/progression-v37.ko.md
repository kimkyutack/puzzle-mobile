# 난이도 곡선과 구역 맵 v37

> 이 문서는 이전 배포 기록이다. 대형 차양과 공유 내구도 중심의 구역 맵은 사용자 영상의 의도를 잘못 해석한 구성으로, 현재 새 판은 `progression-v39.ko.md`의 칸별 상자와 양 끝 타격 자석 레일로 대체했다. 이미 저장된 v37 판은 그대로 이어간다.

## 적용 방식

콘텐츠 버전은 `garden-2026.11.06-progression-v37`이다. 기존 1~30레벨과 물길·동물 길 스테이지는 유지한다. `progressiveLevel`은 1.8.0 호환 요청의 새 판에만 별도 승인 데이터를 선택한다. 이전 엔진의 공개 맵과 `getLevel`의 원본 카탈로그는 변경하지 않는다.

운영 API의 `publishedLevel`이 조정된 정의를 선택하고, `/levels/next`는 해당 맵 버전과 전체 정의의 해시를 반환한다. `/runs/start`도 동일한 정의를 검증해 `Run.level`에 보관한다. 서버는 시작할 때 탐색·재제작을 실행하지 않는다. 진행 중인 판은 기존 `Run.level`과 상태를 그대로 이어간다. 맵 데이터 변경에는 새 게임 엔진 규칙을 도입하지 않았다.

## 난이도 곡선

| 구간 | 구성 |
|---|---|
| 1~30 | 기존 학습 구간 유지 |
| 31~100 | 일반 판 63개 조정. 색 수집 목표 +5% 또는 +12%, 51레벨 이후 일부 상자 내구도 보강, 이동 여유 축소 |
| 101~200 | 차양으로 아래 화단을 여는 간단한 구역. 101~103은 소개·연습, 이후 10판 중 어려움/매우 어려움 2판에 배치 |
| 201~400 | 차양과 굽은 물관을 조합. 10판 중 최대 4판에 배치 |
| 401~700 | 두 차양, 물관, 2×2 씨앗 저장함으로 공략 순서를 구성. 10판 중 최대 5판에 배치 |
| 701 이후 | 일반 판에는 세 구역 구조, 어려움/매우 어려움에 굽은 긴 물관·대형 장치·겹 상자를 조합한 높은 밀도 배치. 10판 중 최대 6판 |

소개·연습 구간은 위 빈도를 우선하며, 쉬운 판과 10판 단위 스토리 스테이지는 복합 구역으로 바꾸지 않는다. 현재 공개 범위 20,000레벨까지만 공급한다. 미공개 번호를 이 데이터로 우회 공개하지 않는다.

31~100 일반 판의 평균 이동 예산은 15.56회에서 13.56회로 줄었다. 새 구역 데이터는 47개의 승인 변형이며, 47개의 새로운 기믹이라는 뜻은 아니다. 기존 차양·물관·상자·저장함 규칙과 PNG를 재사용하고 공간·색·내구도·좌우 배치를 조합했다. 목표 종류는 최대 4개다.

## 검증

- `node --import tsx tools/level-validation/progressive-build.ts --verify`: 초기 조정 63개와 구역 변형 47개, 총 110개의 구매 없는 승리 기록을 실제 엔진으로 재생한다. 초기 자동 매치, 선택지 부족, 강제 섞기가 있는 후보는 승인하지 않았다.
- `tests/progressive-content.test.ts`: 구간별 빈도, 쉬는 판, 대형 장치 도입, 기존 엔진 보존, 목표 수, 공개 슬롯 전체의 데이터 존재, 무작위 시작의 초기 유효성 및 서버 정의 일치를 검사한다.
- `tests/api-campaign.test.ts`: 새 난이도 데이터와 같은 엔진의 기존 저장 판이 함께 존재할 때도 기존 판을 그대로 이어가는지 검사한다.
- 실제 Chrome에서 104레벨 5수 클리어·입력 해제, 104/204/404/708레벨의 차양·굽은 물관·대형 저장함·고밀도 배치를 확인했다. 화면 폭은 테스트 셸 390 CSS px이며 실물 기기 검수는 아니다.
- 전체 69개 파일 / 477개 테스트, TypeScript 및 운영 Worker 패키징 통과.

승리 기록은 작성된 시작 배치에 구매 없는 해법이 있다는 증거다. 무작위 재도전 배치 전체의 승률이나 사람의 난이도를 인증하지 않는다. 실제 테스터의 시도 수·실패 원인에 따라 같은 콘텐츠 버전의 저장 판을 덮어쓰지 않는 후속 조정이 필요하다.

## 자료와 배포

`output/verification/progression-v37/`에 승인 결과, 전체 테스트, 화면 비교, 네이티브 리소스 해시, 배포 로그와 운영 HTTP 검증 결과를 보관한다. 토큰을 담는 임시 QA 세션은 무시되는 `.wrangler` 아래의 0600 파일로만 보관하고 검사 후 제거한다. 운영 검사는 새로 만든 QA 계정 한 개만 사용한다.

앱 리소스는 운영 HTTPS API 설정으로 iOS·Android에 동기화한다. iOS 1.06(7), Android 1.05(6)의 기존 버전 번호를 유지한다. Archive/스토어 업로드는 수행하지 않는다. 최종 운영 버전과 완료 결과는 `production.json` 및 `deploy.log`를 기준으로 확인한다.
